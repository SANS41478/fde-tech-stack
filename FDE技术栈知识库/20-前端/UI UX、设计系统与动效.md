# UI UX、设计系统与动效

> [!abstract] 定位
> [[React]]、[[Next.js]] 和 [[Tailwind CSS]] 解决「怎么写界面」；本篇解决「界面是否好用、是否一致、如何让 AI 按规范实现」。FDE 的 UI 目标不是装饰，而是让用户快速理解、完成任务并获得反馈。

## 一、先区分 UI 与 UX

- **UI**：颜色、字体、间距、组件、布局、动画等可见表现。
- **UX**：用户是否知道下一步做什么、操作是否顺畅、出错后能否恢复。

每个页面至少设计这些状态：

```text
默认 / Loading / 空数据 / 成功 / 失败 / 重试 / 禁用 / 权限不足
```

## 二、设计输入与工具

| 目标 | 可选工具 | 适合 |
| --- | --- | --- |
| 快速探索视觉方向 | Google AI Studio、Stitch、v0 | AI 原型和界面草图 |
| 建立可协作设计稿 | Figma | 组件、标注、交付 |
| 生成全栈原型 | Lovable | 快速验证流程 |
| 直接实现 | React + Tailwind + shadcn/ui | 可维护产品代码 |

推荐流程：

```text
需求与用户流程
  ↓
低保真线框 / 页面状态
  ↓
视觉方向与组件
  ↓
真实数据原型
  ↓
可用性验证
  ↓
工程化实现
```

不要从一张漂亮截图直接开工；先确认用户任务、数据状态和错误路径。

## 三、设计系统最小组成

### Design Tokens

```text
颜色：background / foreground / primary / danger
间距：4 / 8 / 12 / 16 / 24 / 32
字号：caption / body / title / display
圆角：sm / md / lg
阴影：低层级 / 浮层 / 模态框
断点：mobile / tablet / desktop
```

Token 应集中定义，组件只引用语义名称，不在页面里散落几十种颜色和间距。

### 组件层级

```text
基础元素：Button / Input / Badge
组合组件：SearchBar / FormField / DataTable
业务模块：TicketPanel / CRMCard
页面模板：Dashboard / DetailPage
```

组件需要明确：

- 变体和尺寸
- Loading、Disabled、Error 状态
- 键盘操作和焦点表现
- 移动端行为
- 是否允许业务层覆盖样式

## 四、响应式、可用性与性能

- 移动端优先，使用内容断点而不是设备型号断点。
- 触摸目标足够大，焦点状态可见。
- 颜色不能是唯一的信息载体，错误应配文字或图标。
- 表单标明必填、格式和错误位置。
- 破坏性操作先确认，完成后提供撤销或恢复路径。
- 首屏优先加载关键内容，非关键图片和动画延迟加载。
- `prefers-reduced-motion` 开启时减少非必要动画。

## 五、动效选型

| 需求 | 推荐 |
| --- | --- |
| React 元素进出场、布局变化 | Motion |
| 时间线、复杂缓动、滚动驱动 | GSAP |
| 3D 场景和 WebGL | Three.js |
| 设计稿导出的矢量动画 | Lottie |
| 简单 hover / transition | CSS |

动效应该回答一个问题：

```text
它是在表达状态变化、空间关系、因果反馈，还是只是让页面晃动？
```

优先使用：

- 列表交错入场：帮助用户理解顺序。
- 骨架屏：表达数据正在加载。
- 悬浮抬起：表达可点击。
- 数字滚动：表达数值变化。
- 页面过渡：表达导航前后关系。

避免：

- 无限循环的无意义呼吸和抖动。
- 阻塞用户操作的过长动画。
- 大面积模糊、粒子和 3D 导致低端设备卡顿。

## 六、高级效果分类

### 视觉效果

- 渐变边框、光晕、渐变文字、毛玻璃
- 噪点、流光、极光背景
- 视频文字遮罩、混合模式

### 交互效果

- 图片对比滑块
- 搜索框展开
- 手风琴和 FAQ 展开
- 鼠标跟随、聚光灯、磁吸按钮
- 悬浮媒体预览和 3D 模型交互

### 滚动效果

- 滚动触发动画
- 滚动进度条
- 视差和景深模糊
- 横向滚动、卡片堆叠
- 无限滚动和固定定位

实现前先验证基础版本，再逐步增加效果；不要让特效掩盖信息架构问题。

## 七、让 AI 记住设计规范

1. 让 AI 扫描现有页面，提取颜色、字号、间距、组件和反模式。
2. 把结果整理成 `design-system.md`。
3. 将可执行规则封装为项目 Skill，见 [[Claude Code 工作流与项目配置]]。
4. 在 CI 或视觉回归中检查关键页面。
5. 新增组件时更新规范，避免设计系统漂移。

提示词示例：

```text
请先扫描现有页面，提取设计 token、组件变体、响应式断点和重复样式。
不要立即重写页面。先给出设计规范草案和不一致项，等待确认。
```
