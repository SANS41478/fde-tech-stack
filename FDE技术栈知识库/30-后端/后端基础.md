# 后端基础

> [!abstract] 定位
> **后端** 是藏在服务器里、用户看不见但真正干活的部分：收请求、算逻辑、操作数据、返结果。理解「一次请求怎么走完」比记住某个框架更重要。往下接 [[REST API]] 与 [[FastAPI]]。

---

## 一、前端 vs 后端

| | 前端（Frontend） | 后端（Backend） |
| --- | --- | --- |
| 跑在哪 | 用户浏览器 / 手机 | 服务器（云 / 本地 / 容器） |
| 用户看到 | 界面、按钮、图表 | 无界面，只出数据 |
| 职责 | 展示 + 交互 | 业务逻辑 + 数据存储 + 鉴权 |

> [!note] 类比
> 前端是餐厅的菜单和点餐界面，后端是厨房：你点完（发请求），厨房做菜（业务逻辑）、从冰箱取食材（查 [[PostgreSQL]]）、把菜递出来（返回 JSON）。

### 一·补、常见混淆：Node.js / REST API / 后端框架 不是一回事

很多人把这三样都叫「后端框架」，其实是**三个不同层**：

| 名称 | 它到底是什么 | 类比 | 例子 |
|---|---|---|---|
| **Node.js** | **运行时（Runtime）**：让 JS 在服务器跑起来 | 工厂的「发电机」 | 类似 Python 解释器 |
| **REST API** | **接口设计风格/约定**：规定接口怎么设计 | 产品的「规格图纸」 | 同类还有 GraphQL |
| **后端框架** | **工具库/框架**：封装路由、解析、中间件 | 工厂里的「流水线设备」 | Express、FastAPI、Django |

- **Node.js** 解决「代码在哪跑」（运行环境）；它常配框架（Express/Koa/NestJS）写后端。
- **REST API** 解决「接口长什么样」（设计约定）；不关心你用 Node.js、Python 还是 Go 实现。
- **后端框架**（Express/FastAPI）解决「怎么方便地写」（工具）。

串起来：`Node.js（运行时）→ Express（框架）→ 按 REST（风格）设计的接口`。换成 Python 侧就是 `Python → FastAPI → REST 风格接口`。详细见 [[Node.js]] 与 [[REST API]]。

## 二、一次请求的生命周期

```text
浏览器/App  ──HTTP请求──▶  后端服务器  ──▶  路由处理函数
   ▲                         │                  │
   │                         │            查/写  ▼
   └────HTTP响应(JSON)────   └─────────▶  数据库
```

1. 用户在前端点「登录」→ 前端拼 `POST /login` 带上账号密码。
2. 请求经网络到达服务器（某台机器 / 容器）。
3. 后端按 URL（`/login`）找到对应**路由（处理函数）**。
4. 函数校验 → 查库比对 → 生成 token。
5. 把结果（如 `{"token":"abc"}`）包装成 HTTP 响应发回。
6. 前端拿到 token，后续请求带上它证明身份（见 [[JWT]]）。

## 三、核心名词

- **HTTP**：浏览器与服务器对话的「普通话」。方法：`GET` 取、`POST` 提交、`PUT/PATCH` 改、`DELETE` 删；状态码：`200` 成功、`404` 找不到、`500` 服务端炸、`401` 没登录。
- **API（接口）**：后端对外暴露的「能力清单」，按约定格式调用，不必知道内部实现。
- **JSON**：前后端交换数据的通用文本格式，如 `{"name":"张三","age":18}`。
- **路由（Route）**：URL 路径 → 处理函数的映射（如 `/users` 对应「返回用户列表」）。
- **中间件（Middleware）**：请求/响应经过的「公共拦截层」，常用于日志、CORS（跨域）、鉴权。
- **鉴权 / 授权**：确认「你是谁」（认证）和「你能干啥」（授权），见 [[OAuth]] / [[JWT]]。
- **数据库**：持久存数据的地方（见 [[PostgreSQL]] / [[Redis]]）。

## 四、本地运行的后端，还需要 HTTP 吗？

**需要。** 这是常见误区。

- 「本地」改变的只是 **IP（变成 `127.0.0.1` / localhost）和物理链路（变成操作系统内部的回环网卡 loopback）**，**协议栈一模一样**。
- 前端（浏览器）只能通过网络协议访问服务器，它不知道也不关心服务器在不在同一台机器。所以前端调本地后端，那一下仍是 HTTP 请求：`浏览器 ──HTTP──▶ localhost:8000`。
- 后端「接收」HTTP 是对外提供服务；后端也可能「发送」HTTP 去调别的服务（如 [[LLM API]]、微服务互调）。但后端连数据库通常不走 HTTP（PostgreSQL 用自有 TCP 协议）。
- 完全不用 HTTP 的情况：服务端渲染（后端直接吐 HTML，前端无独立 API 调用）、同进程内函数调用、或用 gRPC / WebSocket / 消息队列等别的协议——但浏览器能直接消费的仍主要是 HTTP。

> [!tip] 一句话
> 本地 ≠ 不用协议。只要架构是「前端 ↔ 后端 API」分离模式，哪怕全在一台电脑，前端访问后端那一下永远是 HTTP。这也解释了为什么 [[FastAPI]] 写法与部署位置解耦。
