# 云服务模型

> [!abstract] 定位
> **云服务模型** 不是四种「产品」，而是四种「责任划分档位」。核心认知：**云厂商不只卖硬件，还把系统内部的软件栈一层层托管掉**——你不愿管的下层（硬件、OS、数据库高可用、备份、扩缩容）它替你运维，你只聚焦上层业务。与 [[部署方式]] 配合理解「用什么形态跑」。

---

## 一、责任分界线（从下到上谁管什么）

```text
层级            你管的                云厂商管的
─────────────────────────────────────────────────
本地/裸金属      硬件→OS→运行时→应用→数据   （全自己管）
IaaS(EC2)        OS→运行时→应用→数据     硬件+网络+虚拟化
PaaS            应用→数据               OS+运行时+扩缩+HA
FaaS/Serverless  函数代码+数据           运行时+扩缩+机器全托管
SaaS            只用                  一切（如 Gmail / 飞书）
```

> [!tip] 一句话
> 越往下越可控越便宜但要管得多；越往上越省心但越贵 / 越受限。云的价值 = 把你不想管的下层替你托管。

---

## 二、四种模型

- **IaaS（基础设施即服务）**：给你虚拟机 / 存储，你管 OS 及以上。例：EC2、阿里云 ECS。
- **PaaS（平台即服务）**：给你运行环境，你只管代码 / 数据。例：Heroku、Cloud Run、Railway。见 [[部署方式]] 的 PaaS 段。
- **SaaS（软件即服务）**：成品软件，直接用。例：Gmail、Salesforce（见 [[SaaS 集成]]）。
- **FaaS（函数即服务 / Serverless）**：只写函数，按调用付费，无常驻机器。例：Lambda、Cloud Functions。见 [[Serverless]]。

---

## 三、和「云厂商卖什么」的关系

你之前看到的 AWS 名词（EC2 / S3 / RDS / Lambda / ECS-EKS / CloudFront / IAM）横跨这些模型：

| 服务 | 所属模型 / 层 |
| --- | --- |
| EC2 | IaaS 计算（裸虚机） |
| S3 | 对象存储（IaaS 层资源） |
| RDS | 托管数据库（PaaS 性质） |
| Lambda | FaaS |
| ECS / EKS | 容器编排平台（建在 IaaS 之上） |
| CloudFront | CDN（网络分发层） |
| IAM | 横切所有服务的安全基座 |

> [!note] 它们不是并列清单
> EC2 是地基之一，ECS/EKS 建在 EC2 上，Lambda 是另一路线，S3/RDS 是配套资源，CloudFront 是网络，IAM 套在所有人头上。详见 [[云平台]] 的「AWS 服务不是并列关系」一节。
