# 云平台（AWS / GCP / Azure）

> [!abstract] 定位
> **云平台** 是 FDE 把方案真正上线运行的地方。主流三家：AWS、GCP、Azure。FDE 不一定要成为云架构师，但应 **深入掌握至少一家**，能独立完成「代码 → Docker → 服务器 → 域名 → HTTPS → 上线」。

---

## 一、为什么 FDE 要懂云

> [!quote] 核心
> FDE 不只是「能写出来」，更要「能部署出来」。客户要的是上线的可用系统，不是本地的 Demo。

---

## 二、三家怎么选

| 云 | 特点 | 适合 |
| --- | --- | --- |
| AWS | 服务最全、生态最大 | 通用、企业客户多 |
| GCP | 数据与 AI 强（BigQuery、Vertex） | AI / 数据重 |
| Azure | 企业微软栈集成 | 用 M365 / 微软生态的客户 |

> [!tip] FDE 策略
> **先深入一家**，能力可迁移；客户指定哪家就用哪家。

---

## 三、以 AWS 为例的必会清单

```text
EC2        # 虚拟机，跑 [[Docker]] 容器
S3         # 对象存储（文件 / 模型 / 备份）
RDS        # 托管 [[PostgreSQL]] / MySQL
Lambda     # 无服务器函数（事件处理）
ECS / EKS  # 容器编排（跑 Compose/K8s）
CloudFront # CDN / 静态分发
IAM        # 权限与密钥管理（安全核心）
```

GCP 对应：Compute Engine / Cloud Storage / Cloud SQL / Cloud Run / GKE / IAM。
Azure 对应：VM / Blob / Azure DB / Functions / AKS / Entra ID。

---

## 三·补、AWS 服务不是「并列清单」

新手常把上面七个词当成同一层的并列项，其实它们横跨不同类别与模型（详见 [[云服务模型]]）：

| 服务 | 所属层 / 模型 |
| --- | --- |
| EC2 | IaaS 计算（裸虚机） |
| S3 | 对象存储（IaaS 层资源） |
| RDS | 托管数据库（PaaS 性质） |
| Lambda | FaaS（见 [[Serverless]]） |
| ECS / EKS | 容器编排平台（建在 EC2 之上，见 [[部署方式]] / [[微服务]]） |
| CloudFront | CDN / 网络分发层（见 [[静态托管与边缘]]） |
| IAM | 横切所有服务的安全基座 |

> [!note] 关系图
> IAM（套在所有人头上的权限）┤ EC2（地基）→ ECS/EKS（在虚机上跑容器编排）┤ Lambda（另一路线）┤ S3/RDS（配套资源）┤ CloudFront（网络）。它们逻辑上并非并列，而是「一个系统里不同职责的服务」。

---

## 三·补二、国际三大之外：国内云

只提 AWS/GCP/Azure 是因英文生态与全球覆盖，不是国内云技术弱。国内主流：阿里云、腾讯云、火山引擎、华为云，按「用户在国内 → 国内云更优；出海 → 国际三大」选择（合规 + 数据驻留 + 备案）。详见 [[国内云]]。

---

## 四、FDE 上线最小路径

```text
代码
 ↓ [[Docker]] 镜像
 ↓ 推到云（Registry）
 ↓ 服务器（EC2 / Cloud Run / ...）
 ↓ 域名 + HTTPS（证书）
 ↓ 上线
```

配套：
- 用 [[Docker Compose]] 或云原生编排起服务。
- 用 [[CI-CD|CI/CD]] 自动部署。
- 用 [[Linux]] 登录排查。

---

## 五、安全与成本

> [!warning]
> - **IAM 权限过大**：遵循最小权限，别给 admin 通配。
> - **密钥硬编码**：用云密钥管理 / 环境变量，见 [[企业系统集成]] 安全。
> - **忘了关机**：测试实例一直开着，月底账单惊人，养成清理习惯。
> - **无监控**：服务挂了不知道，见 [[Debugging 与可观测性]]。
