# 公网访问、域名与 HTTPS

> [!abstract] 定位
> 本篇串起「本机能看 → 局域网能看 → 临时公网分享 → 正式域名上线」的路径，补充 [[部署方式]] 和 [[静态托管与边缘]] 中缺少的 DNS、证书和访问排查。

## 一、三种访问层级

```text
localhost：只有本机
局域网 IP：同一网络设备可访问
内网穿透：临时把本地端口映射到公网
正式部署：云平台 / VPS + 域名 + HTTPS
```

手机访问本机项目时，先确认：

- 服务监听在 `0.0.0.0` 而不是只监听 `127.0.0.1`。
- 手机和电脑处于同一局域网。
- 防火墙允许对应端口。
- 使用电脑的局域网 IP，而不是 `localhost`。

## 二、内网穿透

Cloudflare Tunnel、ngrok 等工具通过出站连接把本地服务暴露为临时地址：

```text
浏览器 → 隧道服务 → 本地端口 → 开发服务器
```

适合：

- 给客户临时看 Demo。
- 测试需要公网回调的 OAuth / Webhook。
- 移动端联调。

不适合：

- 长期生产服务。
- 暴露管理后台、数据库或调试端口。
- 没有登录和访问控制的敏感项目。

## 三、域名与 DNS

域名解析常用记录：

| 记录 | 作用 |
| --- | --- |
| A | 域名指向 IPv4 |
| AAAA | 域名指向 IPv6 |
| CNAME | 一个域名指向另一个域名 |
| TXT | 验证、SPF、DKIM 等文本信息 |

推荐流程：

```text
注册域名
  ↓
确认平台要求的记录
  ↓
添加 A / CNAME / TXT
  ↓
等待 DNS 生效
  ↓
平台绑定域名
  ↓
签发 HTTPS 证书
```

排查顺序：

```text
DNS 是否解析到正确目标
→ 目标服务是否监听
→ 防火墙 / 安全组是否放行
→ 反向代理是否匹配 Host
→ 证书是否覆盖该域名
```

## 四、HTTPS 与证书

- 使用 Let's Encrypt 等自动签发证书。
- 证书必须覆盖主域名和需要的 `www` / 子域名。
- 开启 HTTP → HTTPS 强制跳转。
- 设置证书自动续期和到期告警。
- 泛域名证书需要 DNS 验证并注意密钥权限。

常见错误：

- 证书域名不匹配。
- 证书过期。
- 代理层和源站协议配置不一致。
- HTTPS 页面加载 HTTP 资源造成 Mixed Content。

## 五、备案与合规

面向中国大陆提供服务时，确认平台、域名和业务是否需要 ICP 备案；不确定时先查注册商、云厂商和监管要求。备案与免备案方案属于部署决策的一部分，不要上线后才处理。

## 六、访问问题清单

- [ ] 本机 `localhost` 可访问。
- [ ] 局域网 IP 可访问。
- [ ] 防火墙和安全组已放行必要端口。
- [ ] 临时隧道没有暴露敏感服务。
- [ ] DNS 记录目标正确。
- [ ] 主域名和子域名都完成绑定。
- [ ] HTTPS 证书覆盖所有入口并自动续期。
- [ ] 生产环境不直接暴露数据库和调试端口。
