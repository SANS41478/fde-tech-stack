# 静态托管与边缘

> [!abstract] 定位
> **静态托管** 把纯前端文件（HTML/CSS/JS，或 React/Next 编译出的静态产物）通过 CDN 全球分发；**边缘函数** 让你的一小段动态代码直接跑在全球边缘节点。本文也解释「AI Agent 一键部署网站」的原理。与 [[部署方式]] 的静态段、[[Serverless]] 互补。

---

## 一、静态托管是部署什么？

部署**纯前端**：只有 HTML/CSS/JS、没有后端逻辑的网站（或 Vue/React 这类「编译后也是静态文件」的前端框架）。平台构建成静态文件，CDN 分发，用户浏览器下载、JS 在本地跑。所以「快且几乎零成本」——只是发文件，没有服务器算逻辑。

典型平台：Vercel、Netlify、Cloudflare Pages、GitHub Pages。

---

## 二、边缘函数（不只是静态）

如 Cloudflare Workers：把你的一小段**动态代码**直接跑在全球边缘节点（离用户几公里），可做鉴权、改写请求、A/B 测试、调外部 API——不需中心服务器。

> [!note] 现代流行形态 = 静态文件 + 少量边缘函数
> 如处理表单提交、登录、轻量 API。后端重逻辑仍走 [[FastAPI]] / [[Serverless]]。

---

## 三、AI Agent「帮你部署网站」是什么原理？

v0 / Bolt / Lovable 等 agent 说「帮你部署」，本质是**代你调用上述 PaaS / CDN 的 API**：

```text
Agent 生成前端代码
   ↓ 调用 Vercel / Netlify 部署接口（或其自有基础设施）
平台构建并托管
   ↓ 返回网址
```

- **是的，是厂商用自己的服务器（或底层租用云）为用户提供托管**，但通常把项目建在「你的账号」下，你拥有那个 Vercel 项目，只是省去手动 `git push` + 配域名。
- 底层仍是「静态托管 + 边缘函数」那套，agent 只是把人工操作自动化。
- 这类部署大多是**前端 + serverless 函数**，跑不了重后端。

---

## 四、FDE 视角

- 给客户做 Demo / 落地页，优先用 Vercel + [[Next.js]] + 边缘函数，几分钟上线、全球快、近乎零成本。
- 需要后端数据时，前端调 [[FastAPI]]（部署在 [[Docker]] / 云），形成「静态前端 + API 后端」组合。
