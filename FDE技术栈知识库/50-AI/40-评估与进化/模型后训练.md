# 模型后训练

> [!abstract] 定位
> 核心公式 Agent = LLM + 上下文 + 工具——本章聚焦优化 LLM 这个"大脑"：先用 **Mid-training** 补齐目标领域知识与基础能力，再用 **SFT/RL** 塑造模型利用上下文和工具的行为。[[Agent 评估]] 的评估体系与仿真环境是后训练的两块基石：评估环境为训练提供练习场，评估指标为训练定义目标。两条贯穿全章、比任何算法都值得记住的判断：**① 数据和环境比算法更重要**（很多场景底座和示范数据到位，根本不需要做 RL）；**② 当前 RL 的主要瓶颈是样本效率与分布一致性**。核心论点："SFT 记忆、RL 泛化"——这是受控实验中观察到的倾向，不是普适规律。

## 一、四阶段全景

| 阶段 | 用什么数据 | 优化目标 | 学到什么 | 典型代价 |
| --- | --- | --- | --- | --- |
| 预训练 | 海量原始互联网文本 | 预测下一个词 | 语言规律、世界知识、基本推理 | 极高（数百万～数千万美元） |
| **Mid-training** | 目标语言/领域/能力语料 + 保留数据 | 继续预测下一个词（通常对全部 token 计损失） | 补齐领域知识、语言和基础能力 | 中到高（取决于 token 规模与是否全参） |
| **SFT** | 几千～几万条"输入—输出"示范对 | 预测下一个词（只在回答上算损失） | 指令遵循、输出格式、风格、流程协议 | 低（几小时～几天） |
| **RL** | 任务、环境 + 奖励信号（参考答案可选） | 最大化期望奖励 | 可迁移的决策策略、探索的新解法 | 高（常是 SFT 的几十～上百倍） |

一个关键点贯穿始终：**模型的输出本质是一个概率分布**——给定前文，对词表每个 token 给出概率；所谓"训练"就是调整这个分布。四个环节的区别只在于"想要什么"和"用什么信号定义想要"。

### 1.1 预训练：预测下一个词

给模型看文本前半部分猜下一个 token；与真实答案的差距叫**损失（Loss）**，越小越准。在几万亿 token 上反复做，被迫学会语法、事实、逻辑乃至基本推理——要在海量语境持续猜对没有捷径。预训练后模型**博学却不好用**：问问题它可能续写出更多问题（互联网文本里问题后面常跟着另一个问题），还没学会"被提问时应该回答"这个协议。

### 1.2 Mid-training：在目标分布上继续学习

通用预训练不可能覆盖所有语言、领域和能力——模型几乎读不懂韩语文档、不了解企业内部协议、没有目标任务所需的代码与长上下文表征时，直接教"如何回答"或只按成败给奖惩都太晚了。Mid-training 沿用下一个 token 目标，**把数据分布收窄到目标领域，混入一部分通用保留数据控制遗忘**。解决两类缺口：**知识缺口**（目标语言、金融/医疗/法律、企业文档、某类代码库——连概念术语都不能理解）与**基础能力缺口**（长上下文、代码模式、数学推导——不只是回答格式不对，而是足够多次采样下也几乎得不到正确解）。

**Mid-training vs SFT**：损失函数看起来像，但数据组织和监督密度不同——前者对整段文档/代码/推导的**全部 token** 计算损失；后者组织成输入-输出示范、通常只在回答 token 上算损失。用少量 QA 对让模型背事实只反复强化少数访问路径，**容易记住问法而不形成广泛可调用的知识**。稳健配方：**Mid-training 吸收知识与能力 → 小规模 SFT 建立输出格式 → 有非零成功率后再 RL 提升成功率与泛化**。动态事实需要频繁更新/引用/删除时仍归 [[RAG]] 管。

**Mid-training 数据构造五步**：
1. **从失败分布反推数据**：按主题、语言、文档类型、代码模式、上下文长度切分评估，确认低 pass@k 来自哪类底座缺口——只针对缺口补数据，**避免把输出格式错误误诊成知识不足**。
2. **构造高密度目标语料**：原始文档建立术语事实关联、代码仓库学结构依赖、教材式推导/合成释义/跨文档关联样本把隐含关系写明确；去重、质量过滤、评估集污染检查。
3. **按能力进行数据配比**：自然长文本（书籍、长文档、代码仓库）+ 长文本原子能力的思维链数据（长文本检索、多跳推理、指令遵循、信息聚合、统计）+ Agent 执行轨迹（规划、工具选择调用、长程状态跟踪、错误恢复）。思维链和 Agent 轨迹可从较强开源模型蒸馏。
4. **每个阶段做"双重回放"**：原始短文本和通用数据（保留语言/知识/短上下文能力）+ "长度提升后的旧任务"（已会的短任务放进当前长度的上下文，不同位置加相关信息和干扰项——检验同一能力在更长窗口是否仍成立）。
5. **多维门禁决定停止**：训练 loss 之外同时跟踪留出领域任务、通用能力、原有指令遵循、目标任务 pass@1/pass@k。领域指标上升但通用保留集下降 = 混合或学习率过激；loss 降而 pass@k 不动 = 检查数据覆盖 + 是否缺访问知识的 SFT。

实验 8-5（继续预训练学韩语）：Mistral 7B v0.3（几乎不懂韩语）用韩语维基百科继续预训练（约 80% 韩语 + 20% 英语缓解灾难性遗忘——是该实验的选择非通用默认值），再用韩语指令数据 SFT——**Mid-training 补知识与语言能力，SFT 教如何用韩语接受指令和组织回答**。注意：继续预训练有遗忘风险——韩语盲评分改善，英语能力下降；**不能免除保留集、事实评估和数据质量审计**。

### 1.3 SFT：换了数据的"预测下一个词"

**第一个需要打通的关键认知：SFT 在数学上和预训练是同一个任务**——都是预测下一个词、最小化同一个损失。差别只有两点：
1. **数据不同**：预训练用原始互联网文本（无结构什么都有）；SFT 用精心准备的"输入—输出"对——模型在这些示范上继续预测下一个词，把"被提问时该怎么组织回答"的协议学了进去。
2. **损失只算在"回答"上（loss masking）**：不希望模型学"怎么提问"，只学"怎么回答"——问题部分 token 屏蔽，只对回答部分回传梯度。**这是 SFT 在工程上与预训练唯一实质性的区别。**

一句话概括：**SFT 用极高的样本效率，把一套稳定的"输入→输出"映射与协议固化进参数——固化的是"格式、风格、流程"这类协议性知识（该怎么说），而非大量事实性知识（知道什么）**。目标明确格式固定的任务几千条样例就见效；数据覆盖面多样性不足时对表面模式或捷径过拟合，分布变化后性能下降。

**LoRA 参数高效微调**（所有后训练的工程默认项）：不动原始大权重矩阵，旁边挂小的低秩"补丁"，参数量仅 1-5% 却接近全参效果；原权重冻结 → 对已有能力扰动更小，灾难性遗忘风险更低。实践经验：**必须应用到所有主要权重矩阵（尤其参数占比最大的 MLP 层，只加注意力层会掉点）；最优学习率约为全参的 10 倍（SFT、RL 都成立）；SFT 用中高 rank（64-256），RL 因每轮信息量小用小 rank（8-32）甚至 rank=1**；一台推理服务器可同时加载多个 LoRA adapter 做多租户。

**SFT 数据从哪来**（三条路，经常组合）：①**人工专家示范**——质量天花板最高但贵且慢，适合定义格式与风格的"种子数据"；②**教师模型生成**——强模型批量产出"输入-输出"对，过滤后蒸馏（合成数据）；③**拒绝采样**——模型对同一问题采样多条候选，验证器筛出正确样本反过来训练自己（RFT，介于纯 SFT 与 RL 之间：不训奖励模型不做策略梯度，只靠"拒绝错的留下对的"提升数据质量，是可验证任务上性价比极高的数据构造手段）。通用流程：定义任务分布与输出 schema → 批量生成候选 → 规则校验+格式检查+人工抽检 → 去重、平衡配比、保证多样性。**不必贪多：数千到数万条高质量样本通常足以固化输出格式——与其堆十万条脏数据，不如精修一万条干净数据：数据里的每一处噪声，SFT 都可能忠实地写进参数。**

SFT 固化的"协议"四例：语音 SFT（风格控制协议——Orpheus 声音 token 克隆、Sesame `<laugh>/<sigh>` 副语言标记）；多语言思考 SFT（reasoning language: German 训练后可零样本切中文——**SFT 只是激活了多语言预训练已有的跨语言共享表征**）；Prompt 蒸馏 SFT（长提示+思考教师 → 短提示+非思考学生）；工具调用 SFT（JSON schema + 错误处理协议）。

### 1.4 RL：从奖励中学习策略

RL 不直接模仿参考回答的 token，而是让模型自己试，把做得好的行为概率调高。要从这种信号学习需满足两个前提：

1. **格式支持**：任务要求 JSON/工具调用而模型输出无法解析——奖励函数连"成败"都判断不了。SFT 先扮演"把话说利索"：少量示范稳定格式与基本流程使奖励可计算，再 RL 优化（"先 SFT 后 RL"）。
2. **能力支持（更根本）**：先在留出任务上以与训练相近的温度采样测 pass@1 和 pass@k。`pass@k = 1-(1-p)^k`。**pass@1 低但 pass@k 随 k 明显上升 = 正确策略已在模型分布里只是概率质量太小——RL、拒绝采样、蒸馏都有东西可放大；pass@k 仍接近 0 = 基础模型几乎生成不出成功轨迹**——只给终点 0/1 奖励时 GRPO 一组 rollout 可能全 0，组内优势消失，PPO 也看不到正向样本。**RL 擅长把已有但概率较低的成功行为推高，不擅长从全零奖励中凭空创造模型从未学过的知识和能力。**

边界："必须先 SFT"只在输出格式或基本行为尚未建立时成立——足够强、已有非零成功率的基模可跳过 SFT（DeepSeek-R1-Zero；它后来加冷启动 SFT 主要为改善可读性与语言一致性，不是注入任务知识）。

### 1.5 SFT 与 RL 的本质区别

| 维度 | SFT | RL |
| --- | --- | --- |
| 优化目标 | 最大化标注答案的概率（极大似然） | 最大化期望奖励 |
| 训练信号 | 标注回答的逐 token 监督 | 策略生成的回答/轨迹 + 结果级或步骤级标量奖励 |
| 数据形态 | "输入—输出"示范对 | 任务、环境 + 奖励信号 |
| 分布漂移下 | 取决于示范覆盖；有限示范实验出现过拟合 | 取决于奖励、环境和探索；实验中迁移更好 |
| 样本效率 | 高（几千条见效） | 低（几十～上百倍） |
| 训练稳定性 | 高、收敛快 | 低、易震荡 |
| 最适合 | 固化格式/风格/流程、有高质量示范 | 需泛化到新场景、探索最优策略、标注成本过高 |

**概率分布视角**：一个问题常有多类合理回答，各对应分布中的一个"峰"。SFT 逐条学习示范，倾向 **mass-covering（覆盖式）**——尽量覆盖训练数据中出现过的多个模式；RL 按奖励重新分配概率，配合反向 KL 约束倾向 **mode-seeking（寻峰）**——集中到少数高奖励峰。

**在线 RL 的三个机会**：①**评估示范之外的候选**——SimpleVLA-RL 发现人类示范中没有的"推切"动作（但奖励无法识别的质量学不到、探索不到的策略发现不了）；②**利用"验证比生成容易"的不对称**——SFT 需先写出正确答案，RL 只需可靠判断答案质量（数学可对照、代码可测试、定理可验证器检查——RLVR 的优势；验证器不完整时导致奖励黑客）；③**在当前策略实际访问的状态上训练**——离线模仿有协变量漂移（策略偏离示范进入数据没有的状态后缺恢复信号，误差最坏随轨迹长度 T² 累积，在线数据聚合可降到约 T）。

**后训练塑造模型何时行动**：GPT 系与 Claude 系 Coding 模型表现出不同的默认行动阈值（先读更多仓库再修改 vs 少量文件快速定位先改再借测试修正）——不是拟人化"谨慎/直觉"，而是**参数中的策略在估计：多读一个文件的预期价值是否还高于提交当前补丁并验证的预期价值**。若 SFT 示范反复包含广泛调查后才编辑的轨迹，模型模仿较高行动阈值；若 RL 奖励持续认可快速定位尽早进入可验证循环，概率质量向较早行动集中。同一中性 Harness 换模确实测到差异随模型变化（见 [[Agent 评估]] 实验 7-8）——**Harness 无需强制流程，模型自身携带稳定的工具使用策略；Harness 可调节它，但行为的主要来源可以在后训练后的参数中**。

## 二、从经典 RL 到现代 Agent [可选阅读]

**标准 RL 循环**：Agent 观察状态 → 选动作 → 环境给奖励并转移到新状态；产生轨迹（状态→动作→奖励→……）；目标是最大化**累积奖励** G = R(1) + γR(2) + γ²R(3) + ...（γ 折扣因子决定多看重未来）。两个区别于监督学习的特征：**试错搜索**（没有老师告诉正确答案）与**延迟奖励**（一步好棋的价值到终局才显现）；由此带来探索-利用权衡。

**MDP 与 Q-learning**：贝尔曼方程核心递归——一个动作的真实价值 = 即时奖励 + 到达下一状态后的最大未来价值：`Q*(s,a) = r + γ max Q*(s',a')`。**时序差分学习（TD）**：用一步实际结果修正旧估计，`Q(s,a) ← Q(s,a) + α[r + γ max Q(s',a') − Q(s,a)]`。Q-learning 属**离轨策略（Off-Policy）**——可用不同于目标策略的探索策略生成的数据学习，但要求充分覆盖状态-动作对。

**实验 8-1（寻宝游戏）**：隐藏机制（钥匙/门的对应、武器效果、物品合成）+ 多步依赖（最优 11 步）+ 稀疏奖励。表格 Q-learning（ε-贪婪，探索率 1.0→0.1）：前 1000 episode 0% 胜率；7000-8000 episode 胜率 34%→96%；10000 episode 100% 胜率、找到 11 步最优解。仿真中 10000 次尝试仅 10 秒；**真实世界每次打电话有成本、每次操作有延迟、每次错误可能不可逆——10000 次试错完全不可接受**。使用预训练 LLM 策略的一个原因正是利用已有知识在更少交互中做出有效决策。

**实验 8-2（Q-learning vs LLM Agent）**：同一寻宝游戏，LLM Agent（Kimi K3，维护 50 条经验缓冲）**第一局就在 18 步内通关**——有目的的探索（拿生锈的剑"武器总比空手好"）→ 机制理解（理解"钥匙自动使用"、预判生锈的剑不够对付守卫，第 8 步主动合成银剑）→ 执行与纠错（第 13 步击败守卫，夹杂一两步无效尝试）。**语义理解 vs 符号映射的根本差异**：LLM 理解游戏的概念结构，每步有目的和逻辑支撑；Q-learning 眼里"门""钥匙""剑"只是无意义符号，靠大量统计学习慢慢发现关系。计算成本悖论：Q-learning 跑 10000 局 10 秒、LLM 一局 1-2 分钟——但现实任务中交互的时间/金钱/风险成本远超计算成本；更关键的洞察：**LLM Agent 的成功不是拥有更好的"学习算法"，而是携带了海量先验知识**——游戏规则变化时 Q-learning 完全重训，LLM 通过推理直接适应。设计原则：**仿真成本低可大量重复 → 传统 RL 仍有价值；交互成本高需快速适应 → LLM Agent 的样本效率更实际**。

**OpenAI 训练范式演进的认知转变（姚顺雨《The Second Half》）**：①2015-2016 算法中心主义（更好算法是关键，换环境从头训练）；②2016-2018 环境的重要性（Gym 标准化任务、Universe 把互联网变训练环境、Dota 2 超人表现——但通用计算机使用和网页导航始终无法突破）；③2018 至今**先验的觉醒**——GPT-2/3 展示语言预训练的强大力量，WebGPT、ChatGPT 证明先验可转化为实用 Agent。**最重要的发现：先验知识可以通过与 RL 完全无关的方式获得（语言预训练）——几十年来 RL 研究者的优先级可能完全颠倒了：不是算法 > 环境 > 先验，而是先验 > 环境 > 算法。**

**两种动作表示**：经典 RL 用预定义有限离散（棋类）或有界连续（机器人关节）动作；**LLM 策略用有限 token 词表和工具 schema 构造变长组合式动作**——最关键的实用创新是把**思考 token 作为特殊动作纳入策略输出空间**：内部思考不直接改变外部环境也不立即获得奖励，但在 token 成本和上下文上限内表达多种计算路径。变长组合式动作搜索空间巨大，没有先验很难从零学——预训练策略给结构化路径更高先验概率，显著压缩搜索空间；即使没有额外 RL，预训练 LLM 也能生成基本思维链。RL 后训练再用外部奖励教会 LLM 在特定任务中更有效地利用这些模式。

## 三、何时选择 Mid-training、SFT 与 RL

**实操诊断：先判断缺的是底座、协议还是策略，不要把"模型做不好"统一归因成需要 RL。**

| 观察到的现象 | 主要缺口 | 优先方法 | 进入下一阶段的门槛 |
| --- | --- | --- | --- |
| 领域概念、语言或基础操作不会；合理采样下 pass@k 仍接近 0 | 知识与能力不在基模的有效支持中 | **Mid-training**；动态事实用 RAG | 领域留出集改善，通用保留集可接受，目标任务开始出现可验证的正确或部分正确轨迹 |
| 偶尔能做对，但格式、工具 schema、语气或固定流程不稳定 | 行为协议没有固化 | **SFT** 或约束解码 | 解析成功率稳定，关键动作和输出协议可被验证器可靠评分 |
| 已有非零成功率和可靠奖励，但好策略概率低、长程决策或 OOD 泛化不足 | 概率质量分配与策略优化 | **RL** | 奖励与真实目标一致；rollout 组内有足够奖励差异；独立测试集随训练改善 |
| 只有少量稳定示范，尚无可交互环境 | 可模仿数据有、在线反馈无 | SFT / RFT / 离线偏好优化 | 先建立基线与评估，再判断是否值得建设 RL 环境 |

**决策顺序**：
1. **先排除不需要改权重的方案**：Prompt、工具、代码约束、上下文管理能解决行为问题就不必训练；事实需频繁更新、引用或删除优先 RAG。
2. **在目标留出集上测能力支持**：不只看贪心 pass@1，固定采样配置下看 pass@k、部分进展率、格式解析率，人工审计失败原因。
3. **用 SFT 立协议，不拿它硬塞知识库**："会做但不会按要求做"时用高质量示范固化 JSON schema、工具调用、术语用法、流程风格；少量事实可随示范学入参数，大量事实知识不应让少数 QA 对承担。
4. **只在有探索空间时上 RL**：当前策略能产生可评分、偶尔成功的 rollout，奖励忠实反映部署目标——RL 才适合把低概率成功策略推高、探索示范外路径。

不是每个项目都依次跑完三种训练——强基模可能直接 RL，格式型任务可能只需 SFT，稳定领域知识可能只做 Mid-training。**关键是每一步都有可测的进入条件，而不是把"Mid-training → SFT → RL"当仪式化流水线。**

## 四、单轮强化学习：记忆与泛化的对照

"单轮" = 任务在一次交互中完成：接收输入、产出输出、获得奖励、无需跨步骤状态。简化设定聚焦 SFT 与 RL 学习机制的根本差异。

**策略梯度最小直觉**：让模型对同一问题多生成几条回答，奖励高的提高概率、奖励低的降低——"奖励高的方向多走，奖励低的方向少走"。**PPO** 在概率比超出指定区间时裁掉代理目标的额外收益（抑制大幅更新，非硬约束），价值网络估计基线算更细的优势；**GRPO** 不训价值网络，用"同一问题的多条回答互相比较"判断每条相对好坏。

```python
# GRPO：一次 rollout 到参数更新的因果链
for prompt in batch:
    group = [rollout(policy, env.reset(prompt)) for _ in range(G)]
    rewards = [verify(trajectory) for trajectory in group]
    advantages = normalize_within_group(rewards)   # GRPO baseline
    update(policy, group, advantages)
```

**实验 8-10（AdaptThink——学会"何时不思考"）**：大型思考模型对所有问题生成冗长思维链，简单问题造成不必要开销。实验先验证直觉：**NoThinking 模式（`<think></think>` 跳过思考）在简单问题上性能相当甚至更好**，只有困难问题 Thinking 才有优势。AdaptThink 用 RL 训练自适应选择模式：约束优化目标（鼓励 NoThinking 同时确保整体性能不降）+ 重要性采样（平衡 Thinking/NoThinking 样本，解决训练初期几乎只产生 Thinking 样本的冷启动——训练初期模型只走 Thinking 分支，NoThinking 分支样本极少学不起来）。本书复现记录（8×H100，step 0→300）：MATH500 准确率 0.8100→0.8180、响应长度 4911→1576（**-67.9%**）；GSM8K 0.7968→0.8188、长度 -53.4%；AIME mean@16 准确率微降、长度 12119→6402（-47.2%）。与 Prompt 蒸馏互补形成"快-慢双系统"：蒸馏降低需要思考的任务比例，AdaptThink 优化剩余任务的触发策略。

**实验 8-11（GeneralPoints——"SFT 记忆、RL 泛化"的系统量化）**：算术思考卡牌游戏（类似 24 点）。两个变体：纯文本 GP-L 与图像 GP-VL。规则变体：训练时 J/Q/K 都计 10，测试时分别计 11/12/13（训练未见数字组合）——严格评估泛化；视觉变体：训练黑色花色（♠♣）、测试红色花色（♥♦）。基于 Llama-3.2-Vision-11B，先 SFT 初始化，相同计算预算下分别扩展 SFT 与 RL（PPO）：

| OOD 测试（相对 SFT Init 基线） | 规则 OOD (GP-L) | 规则 OOD (GP-VL) | 视觉 OOD (GP-VL) |
| --- | --- | --- | --- |
| SFT 扩展 | **−8.1%**（11.5→3.4） | −5.6% | −9.9%（23.6→13.7） |
| RL 扩展 | **+3.5%**（11.5→15.0） | +3.0% | **+17.6%**（23.6→41.2） |

**结论：SFT 在分布外一致下降，RL 一致提升**。机制解释：有限 SFT 数据强化了"遇到 J/Q/K 就当 10 用"的固定模式，测试 J=11 仍按 10 算；结果导向的 RL 更可能强化"重新计算直到得到正确答案"的策略。追踪视觉识别准确率发现：RL 通过结果导向优化改善了底层视觉编码器且与整体提升高度相关；SFT 因过拟合思考 token 模式忽视视觉 token，识别准确率反而下降。**关键前提：未经 SFT 的端到端 RL 完全失败**（Llama-3.2-Vision-11B 这个量级 + 严格结构化输出要求——基础模型无法产生结构化输出，奖励无法计算）；这是特定设定的结论而非普适规律。另一个发现：验证迭代次数越多测得泛化越好（10 次 +5.99% vs 1 次 +0.48%）——**增加测试阶段计算量是泛化提升的重要因素**。

## 五、RL 算法：从 16 次 rollout 到一次参数更新

**GRPO（DeepSeek 提出，今天最常用的 RL 算法之一）**——以 SWE-bench 任务为例（parser.py 空输入触发 IndexError，要求修复且不能改测试）：

1. **让策略模型重复尝试**：同一份初始代码、同一问题描述复制到 16 个相互隔离的沙箱，模型独立解决 16 次——每次都是完整的"阅读代码→修改文件→运行测试→提交结果"，这就是一次 **rollout**。采样随机性使 16 次走出不同路径：有的正确补上边界检查、有的只捕获异常掩盖问题、有的改错文件、有的试图修改测试。
2. **计算奖励**：验证器在干净环境应用补丁并运行测试。16 次中 4 次通过全部测试且未改测试文件 → 奖励 1，其余 12 条 → 0。coding 任务的"奖励计算"不神秘——**用测试和规则判断这次修复对不对**；开放式任务没有确定测试时才需要人类偏好或奖励模型。
3. **计算相对优势**：奖励只说明单条轨迹成败；相对优势说明**相对于同组其他尝试有多好**。组平均成功率 4/16：通过的 4 条高于平均得正优势，失败的 12 条得负优势。**GRPO 的核心就是这种组内比较。若 16 条全部失败或全部成功，大家奖励完全一样，比较不出谁更好，相对优势消失**——RLVP 的路径信号、过程奖励和部分进展奖励解决的正是如何在这些组里恢复有意义的差异。
4. **梯度下降更新策略**：把相对优势转成训练损失，提高正优势轨迹中模型所做选择的概率、降低负优势轨迹的概率。**不是把某个成功补丁原样背下来，而是在许多任务和 rollout 上逐步调整**——以后遇到类似错误时"先复现问题、检查边界条件、修改实现并运行测试"更容易出现，"掩盖异常、改测试、没验证就提交"更少出现。

**时间量级**：复杂 Agent rollout 生成数十轮工具调用，即使 16 条并行，rollout 阶段墙钟时间由最慢的一条决定——假设最慢 rollout 约 2000 秒 + 更新约 600 秒 = 一个 step 约 2600 秒（43 分钟）；训练 100 steps 接近 72 小时。**ReTool 的 RL 训练时间是 SFT 的 200 倍以上（9 天 vs 1 小时）**。

**算法对比**：GRPO 直接比较同一问题的多条 rollout、不需要额外价值模型；PPO 训练价值模型估计每步"通常能做到多好"，更适合需要**细粒度信用分配**的长轨迹；两者都限制单次更新幅度。**DPO** 不同：直接学习事先收集好的"较好回答—较差回答"偏好对，不让当前策略在线生成 rollout。

### On-Policy 优先与数值失配

**先区分两个词**：**Online（在线）**只表示数据在训练中不断通过环境交互产生；**On-policy（在轨）**要求生成 rollout 的行为策略 μ 与当前要优化的策略 π 相同或足够接近。异步集群即使持续在线生成，只要 rollout worker 落后几个 checkpoint，数据已陈旧——统计意义上已有 off-policy 成分。回放旧轨迹、教师完整生成的数据是更明显的 off-policy。

策略梯度要估计当前策略 πθ 下的期望奖励——数据由另一策略 μ 采样就要用重要性比率纠正：`ρₜ = πθ(aₜ|sₜ)/μ(aₜ|sₜ)`。真正新鲜的 on-policy rollout 在参数更新前 ρₜ = 1，训练集中在"当前模型实际会进入的状态"，避免分布错位的高方差修正。Off-policy 优点是旧数据可复用、吞吐高；代价是策略越陈旧 ρ 的分布越重尾——对自回归长序列，严格的前缀或轨迹修正连乘许多 token 比率，少量偏差累积成极大或极小权重。**"On-policy 更好"不是普遍定理，而是在当前 LLM 策略梯度中通常意味着更低的分布偏差和更稳定的优化。**

> [!warning] 看似 On-Policy，仍会被数值误差拖垮
> 大规模 LLM RL 用 vLLM/SGLang 生成 rollout、用 FSDP/Megatron 重算 log probability 和梯度——即使加载同一份权重，浮点精度、归约顺序、张量并行、批大小、KV cache 与 fused kernel 的差异也可能让同一 token 的 logprob 略有不同。**更新前本应为 1 的 ρ 已经偏离 1：名义上同步了权重，数值上把 on-policy 变成了 off-policy**。已有受控实验表明：单独存在的微小 token 级训练-推理差异就可能引发训练崩溃。敏感性来自放大链条：logprob 小误差 → 指数化的概率比偏差 → 长前缀累积（4000 个 token 各 10⁻³ 同向偏差 → 轨迹级比率 e⁴ ≈ 54.6）→ clipping/优势加权改变 → 梯度方向改变 → 奖励和熵坍塌。
>
> **工程检查清单**：①参数更新前用同一批轨迹比较 sampler 与 trainer 的 token logprob，监控 ρ 均值/分位数/最大值、近似 KL、被裁剪比例（最直接的 on-policy 单元测试）；②同步的不只是权重——还包括 LoRA adapter、tokenizer、chat template、模型 revision、位置编码配置；rollout 保存生成时的 behavior logprob；③尽可能对齐采样与训练的精度、并行布局和关键内核；做不到就把差异明确视作 off-policy，采用重要性修正并监控有效样本数，**不要假设 PPO clipping 会自动兜底**；④保持 rollout 新鲜，限制每批数据的更新轮数和异步 staleness——重用旧数据是经过测量的偏差-效率取舍，不是免费加速。

## 六、RL 环境：从评估到仿真

**RL 训练的瓶颈往往不在算法，而在环境是否足够真实、可重置、可并行。**真实 Agent 的电话、付款、文件修改昂贵且不可逆，不能靠无限重试弥补错误；评估环境提供验证器，训练还需要让 Agent 反复试错、承受动作副作用，并在数百万次交互中保持稳定——**环境工程是 RL 的前置条件，不是附属品**。

1. **环境是模型练习的场地**：RL 本质是试错学习，试错必须有场地——仿真环境。**环境的保真度（与真实部署场景多相似）直接决定训练出的策略能否使用**：仿真里客服总按固定套路回话、错误信息与生产对不上——模型学到一套只在仿真里管用的"应试策略"，一上线就暴露。**这是 RL 项目最常见的失败方式：不是算法不行，而是练习场与考场不同。**构建高保真环境常比训练本身更贵更难。
2. **造不出环境怎么办：让模型扮演环境**。很多场景高保真环境不是"贵"而是根本造不出来——真实 API 有副作用、真实用户不能拿来试错、物理世界没法快进。两个层次：①**模型合成工具调用的返回值**——ZeroSearch 用 LLM 扮演搜索引擎，课程式设计（训练初期返回高质量强相关文档，逐步掺噪声降质量，促使学生学会从真实搜索引擎的不完美结果中提取信息）——训练全程没见过真实搜索引擎的模型直接对接真实搜索仍表现良好；②**模型仿真整个环境的动态**——DreamGym 把环境动态蒸馏进推理式"经验模型"：给定当前状态与动作，逐步推理出状态转移和反馈，不访问真实环境批量合成 rollout。客服、销售 Agent 训练普遍用 LLM 扮演用户（τ-bench 系列正是此思路——**同一个模型模拟器既能当考场也能当练习场**）。**风险：模拟器的世界知识就是训练的天花板，模拟器的系统性偏差会被策略照单全收**——RL 会主动寻找并利用模拟器漏洞进行 reward hacking（模拟的客服比真实用户有耐心、模拟搜索从不返回垃圾结果 → 学到只在"模型扮演的世界"成立的策略）。稳妥做法：**混合——模型模拟承担大部分交互量，辅以真实环境交互，用真实交互定期校准模拟器偏差**。
3. **环境、任务分布与评估隔离**：环境必须可重置、可并行、可复现，状态转移后给出可信验证。训练任务来源与 SFT 数据合成一致——从真实业务日志提炼任务蓝图，去除身份信息后重新生成虚构的人物、订单、文件与状态。**RL 场景多一条：训练环境和评估环境可以共享任务生成器与验证代码，却不能共享同一批任务**——测试用例、隐藏状态和参考解法留在验证器一侧。先少量 rollout 检查"任务可完成、验证器能区分对错"再扩大采样；**验证器本身有系统性偏差时，RL 只会更快地利用它**。确定性验证器"便宜"不等于"没有成本"——容器执行可能让 CPU 验证速度远慢于 GPU 生成，吞吐量取决于并行的验证器 worker 而非继续堆 GPU。顺序：**任务蓝图 → 可重置模拟器 → 确定性验证器 → 训练/评估隔离 → 少量真实交互校准**。

## 七、从单轮到多轮：任务场景与信用分配

| | 单轮 | 多轮 |
| --- | --- | --- |
| 例子 | GeneralPoints / AdaptThink | V-IRL 导航 / AWorld 工具 |
| 状态维护 | 无 | 跨步骤状态，部分可观测需维护历史 |
| 反馈 | 即时，每步可评估 | 延迟，需判断哪步贡献最大 |
| 信用分配 | 简单 | **困难**（Credit Assignment：最终奖励 +10 该归功于哪一步？步骤 3 犯错但步骤 4 纠正 → 修正比步骤 1-2 的正确更关键） |
| 奖励设计 | 结果奖励即可 | 过程奖励 vs 结果奖励权衡 |
| 探索成本 | 单次生成 | 整条轨迹（10-50 步） |

多轮交互正是 ReAct 循环——每轮是一次思考→行动→观察的迭代，奖励延迟来自"最终结果好坏要在多轮之后才能判断"的结构性约束。

- **实验 8-12（V-IRL-VL 多轮视觉导航）**：真实城市街景连续导航，训练纽约路线测试迁移不同城市并同时改变方向表达和视觉外观——**RL 在规则和视觉 OOD 上都明显优于 SFT**；多轮任务中策略需要学会根据当前观测重新规划而非复现训练轨迹。带价值网络的 PPO，逐步反馈缓解长时序信用分配。
- **实验 8-13（SimpleVLA-RL 结果奖励下的开放探索）**：LIBERO 机器人任务只用成功/失败结果奖励——每任务仅一条演示轨迹做 SFT 冷启动，RL 将成功率**从 17.3% 提升到 91.7%**，并发现演示中没有的"推切"动作。与 V-IRL 对照：**过程信号容易定义时能加速学习；最优路径未知时稀疏结果奖励反而保留更大的探索空间**。

### 工具调用：把环境带进 Agent

接入外部工具后动作不只是"移动或回答"——搜索、执行代码、修改文件、查询数据库、组合 API。信用分配、环境工程和安全约束都成核心问题。

- **Search-R1**：检索增强路线——模型自主决定何时搜索、搜什么，利用返回结果继续推理。
- **ReTool（实验 8-14）**：代码解释器嵌入思考循环——SFT 预热后用交织的文本思考、代码执行、解释器反馈做 PPO。模型学会主动执行、读取错误、自我修正（"先需要用 sympy 求解 x²+2x-8=0" → 代码 → 沙盒反馈 [-4, 2] → 验证 2²+2×2-8=0 ✓）。AIME 2024：SFT 基线 25% → 110 步 52% → **400 步 67%**——代码反馈让模型更快学会精确计算和纠错。
- **AWorld-train（实验 8-15）**：MCP 服务器沙盒（26 个服务器、126 个工具函数：Web 交互/文档处理/多媒体/代码执行/Excel/知识检索），VeRL 接口统一，GRPO/PPO，131K 上下文。重点不是刷 GAIA 指标，而是**跑通可重置、可重放的多工具训练链路**，观察工具调用成功率和组合策略是否随训练改善。

**工具轨迹的关键实现细节**：环境返回的 token 不是策略生成的——**计算策略梯度时应屏蔽这些反馈 token，只对模型自己的思考和工具调用参数回传梯度**。否则模型会被训练去预测沙盒输出，而不是学会如何使用工具。

## 八、奖励设计：如何把任务目标变成学习信号

### 8.1 奖励来自哪里

- **可验证奖励（RLVR）最可靠**：测试用例、数据库断言、状态差异、格式检查直接判断结果。数学答案、代码测试、结构化工具调用都适合从二元结果奖励开始；**规则越确定，奖励越便宜、可复现，也越不容易被钻空子**。
- **RLHF 只作背景**：InstructGPT 流程（人工比较回答 → 训练奖励模型 → PPO 优化）——奖励模型只是偏好的代理，过度优化导致 reward hacking，通常用 KL 正则把策略锚定在 SFT 参考模型附近；DPO 跳过显式奖励模型直接从偏好对离线优化。**不是本章 Agent RL 的主线。**
- **模型评判**：目标难以完全规则化时使用。**生成式奖励模型（GRM）**不只输出分数，还生成"哪里做得好、哪里需要改"的诊断；DeepSeek-GRM 的思路：先归纳任务评价原则 → 按原则评价轨迹 → 用可验证事实检查评价是否正确——反馈更透明，仍需抽样人工校准。
- **区分两个概念**：**reward hacking** = 钻规则或实现漏洞拿高分；**reward seeking** = 模型先在心里建立"评判器会看什么"的模型，再按猜测调整行为——不一定篡改测试或伪造结果，却可能在长程任务中自行设置一个过于简单的检查、刚好通过就提前结束，交付物只满足代理指标没满足真实意图。**"通过了 grader"不能自动等价于"任务完成了"：评判器是意图的代理，训练越强，模型越可能把代理当成目标本身。**

### 8.2 奖励在什么时候给

- **结果奖励（ORM）**：只在 episode 结束时判断任务是否完成——最简单，给策略最大探索自由度；中间路径没有公认标准、最优解未被人类发现时，SimpleVLA-RL 的稀疏成功/失败奖励是合适起点。稀疏反馈让模型难以判断多步轨迹中的具体错误——长期 RL 样本效率受限的原因之一。
- **"过早结束"的判定**：模型说任务完成时，**Harness 在隔离工作区运行模型看不到的验收测试**；通过 +1 未通过 −1。测试必须读取真实文件或环境状态，不能只检查模型是否说了"已完成"——否则模型学会口头承诺验证而不真正验证。评估时把"任务未完成"的**边界集**和"确实已完成"的**保留集**分开：前者观察过早结束率，后者观察是否仍能正常收尾——**避免把模型训练成永远不敢结束**。
- **过程奖励（PRM）**：中间步骤提供反馈（身份验证、工具参数、测试通过数、导航动作）。OpenAI《Let's Verify Step by Step》展示逐步验证在数学推理中的价值。缓解长时序信用分配，却可能**把模型限制在设计者预设的路径上**，标注和验证成本更高。V-IRL-VL（逐步导航反馈）vs SimpleVLA-RL（终点奖励）构成"密集反馈换收敛速度、稀疏反馈换探索空间"的对照。
- **工程路径**：先结果奖励建立可靠基线，再只为真正可验证的中间事件加过程信号。多轮 LLM RL 通常折扣因子 γ=1；PPO 的价值网络或 turn-level 优势负责把终点反馈归因到较早动作，GRPO 把轨迹级优势均摊到生成 token——**长轨迹上需格外注意信号稀释**。

### 8.3 奖励需要表达多少信息

奖励的**密度**和**表示形式**是两件事：标量只答"总体多好"；半标量先给简短理由再给分数；向量按准确性、完整性、成本、安全等维度分别打分；生成式奖励给自然语言诊断、可多次采样汇总。选择原则：**有确定答案或测试 → 二元标量；多个相互独立的质量目标 → 向量或加权标量；开放式难以穷举规则 → 生成式诊断 + 事实校验 + 人工抽检**。**不要为"奖励更丰富"堆叠不可验证的维度——每增加一个评价维度就增加一种被钻空子的可能；先确认信号能在少量 rollout 中产生有意义的组内差异，再决定是否加入训练。**

### 8.4 结果正确还不够：路径约束与 RLVP

结果奖励解决"事情有没有办成"，表达不了"是否按规定办成"——真实 Agent 可能通过改测试文件、跳过身份验证、执行破坏性命令获得表面成功。**RLVP（RL with Verified Penalty）原则：奖励结果，惩罚路径**。针对**可机器判定的、与最终成败无关的结果中性约束**；不能替代对语义意图、交付完整性和早停行为的独立检查。

**非对称验证器**：检测"做了一个坏动作"便宜而可靠；证明"这一步确实朝目标取得有意义进展"很难。总奖励写成 `R = O + βΦ`——O 是任务结果，Φ 是由确定性规则逐动作计算的路径信号（对可验证违规动作扣分，对可验证合规动作或可达子目标给少量部分奖励），两路归一化后合并避免路径信号淹没主目标。**不改变 PPO/GRPO，只改变每一步看到的奖励。**

```python
outcome = verify_final_state(trajectory)        # result, not self-report
path_signal = 0
for step in trajectory:
    path_signal += deterministic_path_signal(step)  # penalty or reachable progress
reward = normalize(outcome) + beta * normalize(path_signal)
```

RLVP 的关键不是"奖励越密越好"，而是**能否恢复组内差异**——纯结果奖励在全败组和全胜组都是零方差、没有梯度；违规动作容易检测、惩罚几乎总能恢复差异；进展奖励只在部分进展可达时有效。设计四点：**只惩罚具体动作，不惩罚"不够努力"；结果奖励始终保留（避免模型学会什么都不做）；每个惩罚最好配一条可达的合规路径；规则必须确定、难以钻空子**。基础策略根本不会采样合规动作时，先用少量示范把这条路径"种"出来，合规行为稳定后再逐步减弱路径塑形。

**实验 8-16**：GRPO + 结果奖励 O 与路径信号 Φ 对比纯结果奖励——TerminalBench 违规次数 **3.71 → 0.66** 而成功率基本持平；miniF2F 上可达的部分奖励把达到 0.9 成功率所需迭代 **7.0 → 4.4**。软件修复中所有 rollout 都无法通过任何测试时进展信号不可达、加入无收益——**先测信号可达性，再决定是否增加奖励维度**。真实部署还需把隐藏验证、轨迹监控和外部终止条件一起纳入 Harness。

## 九、蒸馏：提升样本效率

**样本效率**特指：每次昂贵的环境交互能带来多少有效参数更新。RL 样本效率低的根本原因是**反馈太稀疏**——主流 model-free RL 只在 rollout 结束得到一个成败标量，中间的错误原因、缺少字段、流程提示都没有直接学习信号（客服说"需要信用卡后四位"，模型只能从最终 0/1 结果反复试错，可能数百次交互才偶然学会；人类听到一次就记住）。**蒸馏把一次 rollout 变成密集监督信号**——不必额外探索，同一条轨迹贡献大量梯度。

| 方法 | 轨迹/状态由谁采样 | 每条轨迹的主要监督 |
| --- | --- | --- |
| SFT / 离轨蒸馏 | 人类或教师 | 标注答案的逐 token 监督，**密集** |
| On-policy RL | 当前学生 | 结果或过程奖励，**通常稀疏** |
| **On-Policy Distillation** | **当前学生** | **教师在学生前缀上的逐 token 分布，密集** |

### 9.1 在轨蒸馏（On-Policy Distillation）

"policy"指**谁生成学生将要学习的状态前缀**，不是指谁提供监督。SFT 监督密集却主要覆盖教师会走到的状态——学生部署后早期犯了教师不会犯的错就进入训练数据没覆盖的前缀，后续每步在陌生状态上预测，误差沿长序列累积；On-policy RL 直接在学生自己的状态分布上训练、相关性高，却常只在轨迹结束得到成败信号。**在轨蒸馏把两者组合：学生决定走到哪里，教师负责在学生已经走到的位置告诉它下一步的完整概率分布。**

长度 T 的 rollout 不再只产生一个 0/1 信号，而能产生约 **T 组逐 token 监督**——比离轨 SFT 更贴近学生实际会犯的错，比纯 RL 反馈更密集、方差更低；教师推理增加的是计算，不需要再采环境轨迹（**环境交互昂贵时尤其划算**）。实现：学生预测分布贴近教师分布，最小化 KL 散度——学生生成"先查询 API，再解析返回值……"时，教师可在"查询"这个 token 位置给出"查询"80%、"调用"15%、其余 5% 的分布。

```python
student_trajectory = rollout(student, task)
loss = 0
for state in student_trajectory:
    teacher_logits = teacher(state)
    loss += KL(student_logits(state), teacher_logits)
update_student(loss)
```

数学等任务上达到同等性能所需训练步数约为纯 RL 的 **1/10**。多轮 Agent 中成败信号更晚更稀疏，逐 token 的教师分布能直接指导中间决策；前提是仿真环境足够真实——学生探索到的状态接近部署分布，否则教师对陌生偏差状态的评分也不可靠。**在轨蒸馏同样不是"从零创造能力"的办法**：学生至少要能进入教师可纠正的有效状态，教师策略不能离学生的有效支持太远；基模连目标语言、领域概念或基本动作都没有时仍应先 Mid-training 或离轨示范冷启动。**它优化的也是"学生当前策略所访问状态上的教师 KL"——rollout 引擎与 trainer 的数值一致性检查同样必要，否则名义上的 On-Policy Distillation 也会退化成带分布错位的训练。**"稠密信号胜过稀疏信号"在纯 Agent 场景也得到验证：在"时间感"任务上比较 DPO、四种 RL 与 On-Policy Distillation——前者分别受稀疏奖励、目标错位、rollout 形状不匹配和策略崩溃限制；换成冻结的 Qwen3-32B 教师在学生自己的多轮轨迹上逐 token 对齐后训练平滑收敛，**四种条件下通过率比同源 SFT 基线高出 23 到 47 个百分点**——瓶颈往往不是奖励函数不够复杂，而是每次交互提供的信号不够密。

### 9.2 没有更强的教师怎么办：On-Policy 自蒸馏（OPSD）

在轨蒸馏的硬前提：必须有一个明显强于学生的教师。垂直领域模型现有能力都有不足时没有教师可用。**OPSD：同一个模型分饰教师和学生两角，但看到的上下文不同**——教师版能看到"特权信息"（标准答案或已验证的正确解答）；学生版只看到问题本身，却在自己采样的轨迹上向教师版的逐 token 分布对齐。**对着答案解释学生刚走过的路径，通常比独立探索更容易**——一条 rollout 仍产生密集监督。

```python
student_trajectory = rollout(model, task_without_answer)
loss = 0
for state in student_trajectory:
    privileged_state = add_verified_answer(state)
    teacher_logits = stop_gradient(model(privileged_state))
    loss += KL(model(state), teacher_logits)
update(model, loss + retention_regularizer)
```

privileged_state 只能在训练侧构造、不能泄露给部署时的 Agent；retention_regularizer 代表保留集/风格约束。相比 RLVR：**不要求奖励一定能被自动验证**——特权信息可以是标准答案、人工示范或领域文档，用这些信息替代更强的外部教师，同时保留"在轨采样 + 逐 token 监督"的样本效率优势。边界：**它不会凭空创造新知识**——模型拿着答案也讲不清过程就没有额外信号；朴素 OPSD 可能让模型丢失原有思考风格，需额外正则稳定。

### 9.3 CoT 蒸馏与 Prompt 蒸馏

- **CoT 蒸馏**：把强教师的完整思考轨迹转移给学生。对能力较强的教师做 CoT 蒸馏，同等参数量可恢复教师 **70-80%** 的能力——对不追求前沿、寻求自主可控的团队是最务实的跟随者策略（DeepSeek-R1 发布时同步开源的蒸馏小模型：用 R1 思考轨迹对 Qwen/Llama 做 SFT）。"思维围墙"现象：闭源思考模型通常在输出前对 CoT 改写或摘要（防蒸馏、安全、体验），最有价值的原始思考藏在 API 后——选开源思考模型（DeepSeek V4、Kimi K3、GLM 5.2 直接公开完整思维链）作教师。三步流程：①采集轨迹（目标任务分布采样问题 → 教师生成完整"思考+答案"轨迹 → 规则验证器过滤最终答案错误的轨迹——**错误的思考过程会被学生一并模仿**；"生成候选—验证过滤—只留正确轨迹"即拒绝采样 RFT）；②SFT 训练（问题 → `<think>` 思考轨迹 `</think>` + 最终答案）；③对比评估。代价：**学生继承教师的系统性错误和冗长思考习惯**。
- **Prompt 蒸馏**：把"长提示 + 思考型教师"的行为压缩到"短提示/无提示 + 非思考学生"。教师在完整提示与思考模式下生成高质量答案，训练数据只保留用户输入与最终结论、丢弃冗长提示与中间思考——学生学会"直接给出结论"，相同输入接近教师质量，延迟费用显著降低。两个维度：**大到小**（中小模型替代大模型）与**思考到非思考**（同等规模把显式 CoT 折叠为隐式参数化知识，**20-30 倍响应速度提升**）——不冲突，生产中经常同时用。**蒸馏会继承教师的边界**：教师长尾有系统性错误学生进一步硬编码；教师依赖工具保正确性，单纯输出蒸馏会失去工具的鲁棒性。工程启示：**产品形态稳定、输入分布可预期、成本约束明显时是好的优化手段；探索期或任务未定型时保留显式思考与可编辑的提示工程仍是快速试错的核心。**
- **AdaptThink**（见四）：与 Prompt 蒸馏互补的"快-慢双系统"。

## 十、从问题案例到后训练

评估数据集如何真正变成训练输入：

| 第七章评估资产 | 第八章训练用法 |
| --- | --- |
| 端到端回归任务（含验证器） | RL rollout 任务与可验证奖励（RLVR）；拒绝采样（RFT）的采样池 |
| 轨迹前缀回归任务 | DPO 偏好对、决策边界的 SFT 示范、On-Policy Distillation 的教师状态 |
| 失败归因记录（首个错误步骤与类别） | 过程监督的负标签（PRM）、RLVP 路径惩罚的规则来源 |
| Rubric 多维评分与人工金标集 | 向量奖励的各维度、生成式奖励模型（GRM）的训练与校准数据 |

**案例 1：Coding Agent 过早结束**（测试没跑就宣称"已完成"；三个功能改完两个就收尾；两次失败宣布"不可能完成"）。按第七章分类属"任务完成度与逻辑判断问题"，三类信号都能捕获：用户纠正、点踩、事后审计（宣称完成的轨迹里没有任何测试工具调用）。归因把首个错误定位在"**准备宣称完成**"的决策边界——之前读代码改代码可能都没错，错的是"在缺乏证据时下结论"。训练数据：端到端回归任务把"宣称完成前必须跑通验收测试"写成可验证奖励（测试对模型不可见、宣称完成才运行）；轨迹前缀回归任务截取"准备宣称完成"的边界构造偏好对——**rejected 是过早结束，chosen 是"先运行测试、逐条核对验收条件，再下结论"**（教师生成 + 规则验证器过滤 = 拒绝采样），问题案例少时用数据扩充（换任务类型、换缺失的验证项、换完成措辞）到数百条偏好对，按小配比混入通用任务做 LoRA 微调（避免把"逢收尾必验证"学成新过拟合 + 降低灾难性遗忘）。**评估：边界集 + 保留集缺一不可**——前者检查"未完成时是否继续验证"，后者检查"确实完成时正常宣称完成"（只盯前者会训成每个任务都无限验证的过度矫正）。

**案例 2：中文引号**——"中文文章中的直引号应统一为弯引号"描述了期望但没有可直接训练的规则：同一引号在中文自然语言、英文原文、Markdown 行内代码、代码块、代码注释、JSON、路径中角色完全不同。正确修复是**作用域敏感的最小编辑**（中文可转换、嵌套按中文标点规则；英文原文/代码/JSON/路径/标识符原样保留；无法判断作用域保留原文）。构造：把引号规则写成 Skill；正例覆盖中文段落、嵌套引用、代码注释中的中文；反例覆盖英文原文、字符串字面量、JSON、路径、行内代码、代码块——**教"先判断作用域再做最小编辑"，不是"看到直引号就替换"**。LoRA SFT（Qwen3-8B，1024 训练 + 256 留出 + 256 边界，按 16 类片段 × 10 体裁 × 9 语言渲染）。

**案例 3：编辑文件经常失败**——edit_file(path, old_string, new_string) 按精确字符串匹配，差一个空格/换行/反斜杠/Unicode 组合字符/低频 token 都失败。归因沿链路：文件原始字节 → 工具返回 → Harness 序列化 → 模型上下文 → 模型 token 输出 → 解码字符串 → JSON/tool-call 解析 → 工具匹配——文件读取或工具返回已改字节归因给工具；序列化转义提示词拼装改变归因给 Harness；tokenizer encode-decode 变化归因给 tokenizer；**只有模型收到的上下文与原始完全一致而模型输出是链上首个差异位置，才标为模型的精确复制能力问题，作为后训练候选**。构造三个可验证任务：直接逐字复述；在相似等长字符串中选择完全相同目标；把指定字符串完整抄到 old_string 的工具 JSON 参数——样本特意包含真实编辑最容易损坏的字符。**结果：留出集 byte-exact accuracy 从 37.5% → 78.9%，独立边界集 80.1%**；512 条探针比较三个开源 tokenizer，Qwen3 与 Qwen2.5 无损 round-trip 均为 80.1%——**80.1% 同时反映了模型复制能力和 tokenizer 上限**。

## 十一、后训练实践要点

**常见陷阱（识别它们往往比掌握技术细节更能避免资源浪费）**：

1. **用 SFT 硬塞知识库，或把所有知识都交给参数**——大量稳定领域知识与基础能力用 Mid-training 写入参数，SFT 教如何访问和表达；需要动态更新、引用、权限控制或删除的事实由 RAG 管理。
2. **格式未稳定就引入 RL**——模型不能稳定生成奖励计算所需的 JSON，训练信号稀疏或失真；先小规模评估设格式稳定性门槛，必要时 SFT 或约束解码。
3. **把标称窗口当成有效窗口**——位置编码允许 128K 输入不代表在 128K 上仍会检索、推理和规划；扩窗前完成当前长度能力门禁，每阶段保留短数据和前序阶段 replay，用"能力 × 长度"矩阵检查退化。
4. **pass@k 近零仍直接上 RL**——全失败 rollout 无正向轨迹，GRPO 组内优势消失；先补 Mid-training/SFT 或构造与最终目标一致且可达的课程与部分奖励。
5. **奖励函数设计不当导致奖励黑客**——只看回复长度就生成冗长无意义文本；评估最终目标而非中间指标。
6. **忽视仿真保真度**——仿真过于简化或环境响应不真实，训练出的策略真实场景完全失效；高保真仿真环境的构建成本可能高于训练本身。
7. **过度训练导致泛化下降**——训练损失持续下降但验证集性能恶化 = 死记训练细节；Mid-training 造成通用能力遗忘、SFT 过拟合示范、RL 过度优化奖励与任务分布——**三者都需要独立保留集和早停**。
8. **价值函数崩溃与探索不足**——PPO 价值估计不准导致优势计算偏差、训练曲线剧烈震荡；温度过低陷入局部最优。
9. **把训练-推理数值失配当小噪声**——更新前 sampler/trainer 概率比已偏离 1，on-policy 悄悄变 off-policy；监控 logprob 差异、近似 KL、裁剪比例、策略 staleness。
10. **低估 RL 的计算成本**——SFT 表现良好的任务转 RL 可能需要 10-100 倍训练时间；测试分布与训练高度一致时 SFT 可能已经足够。
11. **训练数据质量低下**——Mid-training 吸收语料错误关联，SFT 直接学习示范噪声，RL 奖励有系统性偏差则把策略朝错误方向放大。

> [!tip] 核心原则
> **大规模投入前，先用小规模实验验证关键假设**——小批 Mid-training 语料检查知识/能力与遗忘曲线；少量 SFT 数据测试格式能否稳定；小批 rollout 检查 pass@k、奖励差异和 sampler/trainer 数值一致性。**快速失败比大规模失败更可接受。**

**与 RAG/ICL 的协同**：三者不互斥，作用于不同位置——**ICL** 用示例、规则和当前状态实现零参数的即时适应（上下文增长则延迟费用上升）；**RAG** 把事实与证据放在可动态更新、可追溯的外部知识中；**后训练**把高维感知、生成风格和隐式决策策略写入参数。选择依据不只是任务是否长期稳定，更重要的是**能力能否被外部符号充分表达**——医疗影像识别、自然语气等能力即使面对持续变化的领域仍往往需要参数更新；反过来，长期稳定的转账审批规则应由代码提供确定性保障，不能只靠模型记忆。稳健系统组合使用：RAG 管动态事实与证据、ICL 快速试验可用语言描述的策略、程序固化确定性流程与硬约束、Mid-training 吸收稳定领域知识和基础能力、SFT/RL 塑造难以由外部规则完整表达的行为、蒸馏把高能力大模型的行为迁移到低成本小模型。
