# Sandbox 与安全 — 沙箱、审批、权限

> [!tip] 目标
> 理解 Harness 如何确保 Agent 不做危险操作。

---

## 1. 为什么需要安全机制

> [!tip] 类比：给实习生钥匙
> 想象你给了一个实习生**公司所有系统的管理员密码**：
>
> - 他可能误删重要文件
> - 他可能泄露敏感信息
> - 他可能执行危险命令
>
> 你需要**限制他的权限**，让他只能做该做的事。

Agent 也是一样——它能执行 bash 命令、读写文件、访问网络。如果不加限制，它可能：

- 删除重要文件
- 访问敏感数据
- 执行危险命令
- 产生意外费用（比如大量调用 API）

---

## 2. Sandbox — 隔离执行环境

> [!tip] 类比：沙盒
> Sandbox = 给 Agent 一个**沙盒**在里面玩：
>
> - 沙盒里的操作不会影响外面
> - 沙盒有边界（不能访问外面的文件）
> - 沙盒可以随时清空

Harness 有三种 Sandbox 实现：

| Sandbox | 用途 | 隔离级别 |
|---|---|---|
| `sandbox-local` | 本地执行（默认）| 低 |
| `sandbox-windows-acl` | Windows 权限控制 | 中 |
| `e2b` | 远程沙箱（Docker）| 高 |

### 本地 Sandbox

```
Agent 在本地执行命令
  │
  ├─ 文件系统策略
  │  只能访问工作目录
  │  不能访问系统文件
  │
  ├─ 网络策略
  │  只能访问白名单域名
  │  不能访问内网
  │
  └─ 进程策略
      不能嵌套执行
      不能启动新进程
```

### 远程 Sandbox（E2B）

```
Agent 的命令在远程 Docker 容器中执行
  │
  ├─ 完全隔离
  │  本地文件系统不受影响
  │
  ├─ 可以随时销毁
  │  容器删了就什么都没了
  │
  └─ 网络隔离
      只能访问指定的网络
```

> [!note] 源码位置
> `packages/sandbox/sandbox-local/` — 本地沙箱
> `packages/sandbox/sandbox-windows-acl/` — Windows 权限
> `packages/e2b/` — 远程沙箱

## 3. 审批系统 — 危险操作前的人类确认

> [!tip] 类比：刷卡门禁
> 审批系统 = **刷卡门禁**：
>
> - 你刷了卡（Agent 请求执行）
> - 门禁检查：你有权限吗？（审批策略）
> - 有权限 → 门开了（允许执行）
> - 没权限 → 需要管理员授权（等待人类批准）

### 审批流程

```
Agent 请求执行危险操作
  │
  ├─ [1] 审批系统检查策略
  │      策略 = "ask" → 需要人类确认
  │      策略 = "never" → 自动拒绝
  │
  ├─ [2] 如果需要确认
  │      发送 approval/request 事件
  │      UI 显示确认对话框
  │
  ├─ [3] 人类决定
  │      allowed-once → 允许这一次
  │      rejected → 拒绝
  │      cancelled → 取消
  │
  └─ [4] 记录决策
         问答和决策都记录到 Session Log
```

### 审批策略

| 策略 | 行为 | 用途 |
|---|---|---|
| `ask` | 每次都问人类 | 交互式使用 |
| `never` | 自动拒绝 | CI/无人值守 |

> [!note] 源码位置
> `packages/interaction/user-approval/` — 审批系统

## 4. 权限预设 — 简化的安全级别

> [!tip] 类比：安全级别
> 权限预设 = **安全级别**：
>
> - **普通员工**：只能访问办公区
> - **经理**：可以访问会议室和办公室
> - **管理员**：可以访问所有区域

Harness 提供了两个权限预设：

| 预设 | 文件访问 | 审批策略 |
|---|---|---|
| `workspace-write` | 工作目录内写入 | 危险操作需确认 |
| `danger-full-access` | 完全访问 | 不需确认 |

用户可以通过 `/permission` 命令切换：

```
/permission workspace-write    ← 切换到普通模式
/permission danger-full-access ← 切换到完全访问模式
```

> [!warning] 警告
> `danger-full-access` 模式下 Agent 可以做任何事，只在你完全信任 Agent 时使用。

## 5. 用户交互系统

### 命令系统

用户可以通过斜杠命令与 Agent 交互：

```
/compact       ← 压缩上下文
/permission    ← 切换权限预设
/preset        ← 切换 Preset
```

### 问答系统

Agent 可以向人类提问：

```
Agent: "你想用哪个框架？React 还是 Vue？"
  │
  ├─ ask_user_question 工具
  │  问题：选择框架
  │  选项：React, Vue
  │
  └─ 人类回答
     选择：React
     Agent 继续执行
```

> [!note] 源码位置
> `packages/interaction/commands/` — 命令系统
> `packages/interaction/user-questions/` — 问答系统

## 6. 安全机制的层次

```
用户请求
  │
  ├─ [1] 权限预设
  │      决定 Agent 的基本权限级别
  │
  ├─ [2] Sandbox
  │      隔离执行环境
  │
  ├─ [3] 审批系统
  │      危险操作需要人类确认
  │
  ├─ [4] 策略检查
  │      文件系统策略、网络策略、进程策略
  │
  └─ [5] 超时控制
      工具执行超时 → 自动终止
```

**每一层都是一道防线**：

| 层 | 作用 | 类比 |
|---|---|---|
| 权限预设 | 基本权限 | 公司门禁卡 |
| Sandbox | 隔离环境 | 沙盒 |
| 审批系统 | 危险操作确认 | 刷卡门禁 |
| 策略检查 | 细粒度控制 | 访问控制列表 |
| 超时控制 | 防止卡死 | 自动断电 |

## 7. 实际安全流程

```
用户："帮我删除所有临时文件"
  │
  ├─ [1] Agent 决定执行 rm -rf /tmp/*
  │
  ├─ [2] 工具系统检查
  │      这是一个危险命令
  │      需要审批
  │
  ├─ [3] 审批系统触发
  │      UI 显示：
  │      "Agent 想要执行：rm -rf /tmp/*"
  │      "这将删除 /tmp 目录下的所有文件"
  │      [允许] [拒绝]
  │
  ├─ [4] 人类点击 [拒绝]
  │
  └─ [5] Agent 收到拒绝
         "好的，我不执行这个命令"
         继续其他工作
```
