# 前置知识 — 最小必要基础

> [!tip] 目标
> 本章用日常类比讲清楚理解 DeepSeek Harness 所需的**最少**背景知识。不需要记住所有细节，后面用到时会反复解释。

---

## 1. 什么是函数

> [!tip] 类比：菜谱
> 函数就像一个菜谱：
> - **输入**：鸡蛋 2 个、西红柿 2 个
> - **步骤**：切、炒、调味
> - **输出**：一盘西红柿炒蛋

在代码里：

```
function 做菜(鸡蛋, 西红柿) {
    切(鸡蛋)
    切(西红柿)
    炒(鸡蛋, 西红柿)
    调味()
    return 一盘菜
}
```

**关键词**：
- `function` = "这是一个菜谱"
- 括号里的 `鸡蛋, 西红柿` = **参数**（输入）
- `return` = **返回值**（输出）
- 花括号里的内容 = **函数体**（具体步骤）

> [!abstract] 技术定义
> 函数是一段可以反复使用的代码块，接受输入（参数），执行操作，返回输出。

---

## 2. 什么是变量

> [!tip] 类比：贴了标签的盒子
> 变量就是一个**贴了标签的盒子**，里面可以放东西：

```
名字 = "小明"      ← 盒子里放了"小明"这个文字
年龄 = 25          ← 盒子里放了 25 这个数字
is_学生 = true     ← 盒子里放了"是"这个判断
```

你可以随时打开盒子看看里面是什么，也可以换掉里面的东西：

```
名字 = "小明"      ← 盒子里是"小明"
名字 = "小红"      ← 换成了"小红"
```

> [!abstract] 技术定义
> 变量是给一个值起的名字，通过名字可以引用或修改这个值。

---

## 3. 什么是 JSON

> [!tip] 类比：填表格
> JSON 就像一张**结构化的表格**，用来描述一个东西的属性：

```json
{
  "姓名": "小明",
  "年龄": 25,
  "爱好": ["读书", "跑步", "编程"],
  "是否学生": false
}
```

**规则**：
- 用花括号 `{}` 包裹
- 每一项是 `"key": value` 的格式
- key 必须用**双引号**包裹
- value 可以是：数字、文字、布尔值（true/false）、数组（列表）、嵌套对象

> [!note] 为什么需要了解 JSON
> DeepSeek Harness 里，工具调用的参数、LLM 的请求和响应，**全部用 JSON 格式传输**。你不需要手写 JSON，但需要能看懂它。

---

## 4. 什么是终端/命令行

> [!tip] 类比：遥控器
> 终端就像电视遥控器——你输入指令，电脑执行：

```
你输入：     dsh web
电脑执行：   启动 DeepSeek Harness 的 Web 界面
你看到：     Server running at http://127.0.0.1:3080
```

**常用命令**：

| 你输入的 | 电脑做的 |
|---|---|
| `ls` 或 `dir` | 列出当前文件夹里的文件 |
| `cd 文件夹名` | 进入一个文件夹 |
| `pwd` | 显示当前在哪个文件夹 |
| `npm install` | 安装项目需要的依赖包 |
| `pnpm run build` | 编译项目 |

> [!warning] 别怕命令行
> 命令行看起来吓人，但它只是另一种"点击按钮"的方式。你输入文字指令，电脑执行。仅此而已。

---

## 5. 什么是 HTTP 请求

> [!tip] 类比：寄信
> HTTP 请求就像**寄信**：

```
你（客户端）                    餐厅（服务器）
    │                              │
    │  ──── 寄一封信（请求）────▶  │
    │     "我要一份宫保鸡丁"        │
    │                              │
    │  ◀──── 回一封信（响应）────  │
    │     "好的，这是你的宫保鸡丁"   │
```

**信封上写着**：
- **地址**：发给谁（URL）
- **方法**：你要干什么（GET = 看看 / POST = 提交 / PUT = 修改）
- **内容**：具体信息（JSON 格式）

> [!abstract] 技术定义
> HTTP 是客户端和服务器之间通信的协议。客户端发送请求（"我要什么"），服务器返回响应（"给你"）。

---

## 6. 什么是 API

> [!tip] 类比：餐厅点餐
> API 就像**餐厅的服务员**：

```
你（开发者）        服务员（API）         厨房（系统）
    │                  │                   │
    │  "我要查用户信息"  │                   │
    │  ─────────────▶  │                   │
    │                  │  ──── 查询 ─────▶  │
    │                  │  ◀─── 结果 ──────  │
    │  ◀─────────────  │                   │
    │  {姓名: 小明}     │                   │
```

你不需要知道厨房怎么运作，只需要：
1. 知道**服务员在哪里**（API 地址）
2. 知道**怎么点餐**（请求格式）
3. 知道**菜品长什么样**（响应格式）

> [!abstract] 技术定义
> API（应用程序编程接口）是一组预定义的规则，让不同的软件可以互相通信。DeepSeek Harness 调用 DeepSeek 的 API 来使用 LLM。

---

## 7. 什么是库/包

> [!tip] 类比：工具箱
> 库（也叫包）就是别人写好的**工具箱**，你可以直接拿来用：

```
你要做一个网页
    │
    ├─ 不用库：自己写所有代码（可能要 1000 行）
    │
    └─ 用库：别人已经写好了，你只需要调用（可能只要 10 行）
```

比如：
- `express` = 做网页服务器的工具箱
- `react` = 做网页界面的工具箱
- `cordis` = 做插件系统的工具箱（DeepSeek Harness 用的就是这个）

> [!note] DeepSeek Harness 的依赖
> Harness 有 54 个自己的包，还依赖大量第三方包。这就是为什么它功能强大——站在巨人肩膀上。

---

## 8. 什么是异步

> [!tip] 类比：排队取餐
> 想象你在快餐店：

```
同步（一个一个来）：
    你点餐 → 等 5 分钟 → 拿到餐 → 下一个人点

异步（同时进行）：
    你点餐 → 拿到取餐号 → 下一个人点餐 → 你的餐好了叫号
```

在代码里，调用 LLM API 需要几秒钟，你不想让整个程序傻等：

```
// 异步：发出请求后不等，继续做别的事
请求结果 = await 调用LLM("你好")   // 等几秒
打印(请求结果)                      // 拿到结果后继续
```

`await` = "等这个完成后，再往下走"

> [!abstract] 技术定义
> 异步操作是发出请求后不阻塞程序继续运行，等操作完成时再处理结果。DeepSeek Harness 大量使用异步，因为 LLM 调用和工具执行都需要时间。

---

## 9. 什么是类型

> [!tip] 类比：快递包裹上的标签
> 类型就像快递包裹上的**标签**：

```
包裹 A：标签写着"易碎品" → 不能扔
包裹 B：标签写着"文件"   → 不能沾水
包裹 C：标签写着"食品"   → 要保鲜
```

在 TypeScript（Harness 用的语言）里：

```
名字: string = "小明"      ← 标签写着"文字"
年龄: number = 25          ← 标签写着"数字"
is_学生: boolean = true    ← 标签写着"是/否"
```

如果试图把数字塞进文字标签的盒子，编译器会报错——这就是类型系统的作用：**防止你把错误类型的数据混在一起**。

> [!abstract] 技术定义
> 类型是数据的分类标签，确保每个变量只存放预期类型的数据。TypeScript 在 JavaScript 基础上增加了类型系统。

## 小结

| 概念 | 一句话解释 | 类比 |
|---|---|---|
| 函数 | 可复用的代码块 | 菜谱 |
| 变量 | 贴了标签的盒子 | 盒子 |
| JSON | 结构化数据格式 | 填表格 |
| 终端 | 文字版的遥控器 | 遥控器 |
| HTTP | 客户端和服务器的通信方式 | 寄信 |
| API | 软件之间的接口 | 服务员 |
| 库/包 | 别人写好的工具箱 | 工具箱 |
| 异步 | 不阻塞的等待 | 排队取餐 |
| 类型 | 数据的标签 | 快递标签 |

> [!tip] 不需要记住
> 这些概念在后面的章节中会反复出现，每次用到时你会加深理解。现在只需要有个印象。
