# 记忆与上下文 — 短期/长期记忆工程实现

> [!tip] 目标
> 理解 Harness 如何管理 Agent 的"记忆"——包括当前对话的短期记忆和跨会话的长期记忆。

---

## 1. Agent 的记忆问题

> [!tip] 类比：金鱼的记忆
> LLM 就像一条**只有几秒记忆的金鱼**：
>
> - 你跟他说了什么？下一轮对话就忘了
> - 他做了什么决定？下一轮对话不知道
> - 他之前犯了什么错？下一轮对话可能再犯
>
> Agent 需要**外挂记忆**来解决这个问题。

---

## 2. 短期记忆 — 当前会话

> [!tip] 类比：工作笔记本
> 短期记忆 = 你在**工作时随手记的笔记**：
>
> - 客户刚才说了什么需求
> - 我刚才做了什么决定
> - 这个任务进行到哪一步了
>
> 工作结束后，笔记可以存档或丢弃。

在 Harness 里，短期记忆就是 **Session Log**：

```
Session Log 记录了：
├── 用户说了什么（user/message）
├── LLM 回复了什么（assistant/message）
├── 调用了什么工具（tool/call）
├── 工具返回了什么（tool/result）
└── 每一步的状态（turn/start, step/start, ...）

LLM 需要"回忆"时，从 Session Log 推导消息历史
```

**短期记忆的容量**：受 LLM 的**上下文窗口**限制（比如 128K tokens）。当对话太长，需要压缩。

---

## 3. 长期记忆 — 跨会话持久化

> [!tip] 类比：存档文件
> 长期记忆 = **存档文件**：
>
> - 上次对话做了什么决定
> - 项目的状态是什么
> - 用户的偏好是什么
>
> 新对话开始时，可以加载这些存档。

在 Harness 里，长期记忆通过 **Session 持久化**实现：

```
会话结束
  │
  ├─ Session Log 保存到磁盘
  │   （JSONL 格式，每行一个事件）
  │
  ├─ 下次启动时加载
  │   重放日志 → 重建状态
  │
  └─ 从断点继续
      不需要重新开始
```

---

## 4. System Prompt — Agent 的"人格"

> [!tip] 类比：员工手册
> System Prompt = 公司给新员工的**员工手册**：
>
> - 你是谁（角色定义）
> - 你能做什么（能力范围）
> - 你不能做什么（安全限制）
> - 你应该怎么做（行为准则）

在 Harness 里，System Prompt 由 `system-prompt` 组件组装：

```
System Prompt 组装过程：
  │
  ├─ [1] 基础人格
  │      "你是一个编程助手..."
  │
  ├─ [2] 工具列表
  │      "你可以使用以下工具：bash, read_file, ..."
  │
  ├─ [3] 注入的上下文
  │      当前时间、工作目录、环境信息等
  │
  ├─ [4] 插件添加的内容
  │      Skill 内容、Goal 状态等
  │
  └─ [5] 渲染成最终的 System Prompt
         发送给 LLM
```

> [!note] 源码位置
> `packages/core/system-prompt/` — Prompt 组装和渲染

---

## 5. 上下文窗口 — LLM 的"工作记忆容量"

> [!tip] 类比：办公桌的大小
> 上下文窗口 = **办公桌的大小**：
>
> - 桌子越大，能同时摊开的文件越多
> - 桌子越小，能同时处理的信息越少
>
> LLM 的上下文窗口决定了它一次能"看到"多少信息。

**上下文窗口的组成**：

```
┌─────────────────────────────────────────┐
│  System Prompt（系统提示）               │  固定开销
├─────────────────────────────────────────┤
│  历史消息（对话记录）                     │  动态增长
├─────────────────────────────────────────┤
│  工具列表（每个工具的描述）               │  固定开销
├─────────────────────────────────────────┤
│  当前消息（用户输入 + 工具结果）          │  动态增长
├─────────────────────────────────────────┤
│  LLM 回复空间                           │  预留空间
└─────────────────────────────────────────┘
         总计不能超过上下文窗口大小
```

## 6. Compaction — 上下文压缩

> [!tip] 类比：整理办公桌
> 当办公桌太乱（上下文太长），需要**整理**：
>
> - 把旧文件归档（压缩历史消息）
> - 保留重要文件（关键决策和结论）
> - 丢弃不重要的（过时的细节）
>
> 整理后，桌子变干净了，但重要信息还在。

Harness 的 Compaction 系统：

```
对话太长
  │
  ├─ [1] 检测到上下文接近窗口限制
  │
  ├─ [2] 触发 Compaction
  │      把旧的对话历史压缩成摘要
  │
  ├─ [3] 替换历史消息
  │      原始历史 → 压缩后的摘要
  │
  └─ [4] 继续对话
         LLM 看到的是压缩后的摘要 + 新消息
```

> [!note] 源码位置
> `packages/compaction/` — Compaction 能力和 Provider

## 7. 注入上下文 — 插件添加额外信息

Agent Loop 在每一步的 `preStep` 中，允许插件注入额外上下文：

```
preStep()
  │
  ├─ 组装基础上下文
  │
  └─ agent/pre-step waterfall
     │
     ├─ 插件 A：注入当前时间
     │  "现在是 2026年8月31日 15:30"
     │
     ├─ 插件 B：注入文件变化
     │  "你刚才修改了 hello.py"
     │
     ├─ 插件 C：注入 Skill 内容
     │  "你有一个叫 'python-best-practices' 的 Skill"
     │
     └─ 插件 D：注入 Goal 状态
        "你的目标是：修复登录 bug，进度 60%"
```

> [!note] 注入方式
> 通过 `agent.inject()` 方法，任何插件都可以向 Agent 注入上下文。注入的内容会等待下一次 LLM 调用时一起发送。

## 8. Runtime Context Projection

Harness 有一个特殊的机制叫 **Runtime Context Projection**，它决定 LLM 能看到什么：

```
完整的运行时状态
  │
  ├─ 文件系统状态
  ├─ 环境变量
  ├─ 工作目录
  ├─ 插件状态
  └─ ...
  │
  ↓ Projection（投影）
  │
LLM 能看到的
  │
  ├─ 当前时间
  ├─ 工作目录
  └─ 插件注入的上下文
```

**为什么需要投影？**

LLM 不需要知道所有运行时细节，只需要知道与当前任务相关的信息。投影确保只发送必要的信息。

> [!note] 源码位置
> `packages/core/agent-loop/src/runtime-context.ts` — RuntimeContextProjection

## 9. 记忆的实际流程

一个完整的记忆流程：

```
用户："帮我修复 login 函数的 bug"
  │
  ├─ [1] 加载短期记忆
  │      从 Session Log 推导消息历史
  │
  ├─ [2] 组装 System Prompt
  │      人格 + 工具 + 注入的上下文
  │
  ├─ [3] 调用 LLM
  │      LLM 看到：System Prompt + 历史 + 新消息
  │
  ├─ [4] LLM 回复：工具调用
  │      "我需要读取 login.py 文件"
  │
  ├─ [5] 执行工具，记录结果
  │      tool/result: 文件内容
  │
  ├─ [6] 工具结果放入短期记忆
  │      等待下一轮处理
  │
  ├─ [7] 下一轮：LLM 看到工具结果
  │      "我发现 bug 在第 42 行..."
  │
  ├─ [8] 会话结束
  │      Session Log 保存到磁盘
  │
  └─ [9] 下次启动
         从 Session Log 恢复
         从断点继续
```

---

## 10. 记忆 vs 上下文

| 概念 | 作用 | 生命周期 |
|---|---|---|
| 短期记忆 | 当前对话的记录 | 会话内 |
| 长期记忆 | 跨会话的持久化 | 永久 |
| System Prompt | Agent 的人格和规则 | 每次 LLM 调用 |
| 上下文窗口 | LLM 一次能看到的信息量 | 每次 LLM 调用 |
| 注入上下文 | 插件添加的额外信息 | 单步 |

---

## 小结

| 概念 | 一句话解释 | 类比 |
|---|---|---|
| 短期记忆 | Session Log | 工作笔记本 |
| 长期记忆 | Session 持久化 | 存档文件 |
| System Prompt | Agent 的人格 | 员工手册 |
| 上下文窗口 | LLM 的工作容量 | 办公桌大小 |
| Compaction | 上下文压缩 | 整理办公桌 |
| 注入上下文 | 插件添加信息 | 同事给你留便签 |
