# 核心概念 — Agent = LLM + 工具 + 循环

> [!tip] 目标
> 用日常类比讲清楚 Agent 的三大组成要素，以及它们如何协作完成任务。

---

## 1. Agent 是什么

> [!tip] 类比：一个新入职的实习生
> 想象你招了一个**超级聪明但什么都不会用**的实习生：
>
> - 他**脑子很好使**（LLM — 大语言模型）
> - 但他**不知道公司的东西在哪**（没有工具）
> - 他**不知道要做什么**（没有目标）
> - 他**做完一步不知道下一步该干嘛**（没有循环）

Agent 就是给这个实习生配上了：

```
大脑（LLM）+ 手脚（工具）+ 工作流程（循环）= Agent
```

> [!abstract] 技术定义
> Agent = LLM（大脑）+ Tools（工具）+ Agent Loop（工作循环）
>
> 这是 DeepSeek Harness 以及所有 AI Agent 框架的核心等式。

---

## 2. 三大组成要素

### 2.1 LLM — 大语言模型（大脑）

> [!tip] 类比：一个读过无数书的人
> LLM 就像一个**读过互联网上几乎所有文字**的人：
>
> - 你跟他说"帮我写一首诗"，他能写
> - 你问他"量子物理是什么"，他能解释
> - 但**他只能说话，不能做事**
> - 他**没有记忆**（每次对话都是全新的）
> - 他**可能说错话**（幻觉问题）

在 Harness 里，LLM 是通过 **API 调用**的：

```
你发送请求 → DeepSeek 服务器上的 LLM 处理 → 返回回复
```

LLM 的输出是一段**文字**，可能是：
- 直接回答你的问题
- 一个工具调用请求（"我需要使用某个工具"）
- 两者的混合

> [!note] 源码位置
> `packages/llm/llm/` — LLM 的 Service Definition + adapter seam
>
> `packages/llm/llm-deepseek/` — DeepSeek 原生适配器

---

### 2.2 Tools — 工具（手脚）

> [!tip] 类比：工具箱
> 工具就是 Agent 的**手和脚**，让它能**做事**而不仅仅是**说话**：
>
> - **Bash 工具**：能在电脑上执行命令（像打开了终端）
> - **文件工具**：能读、写、编辑文件（像有了文件管理器）
> - **搜索工具**：能搜索网页（像有了浏览器）
> - **自定义工具**：你能添加任何工具

每个工具由两部分组成：

```
工具 = 一个函数（做什么）+ 一个描述（告诉 LLM 这个工具能干什么）
```

比如 `bash` 工具：

```json
{
  "name": "bash",
  "description": "在终端中执行命令",
  "parameters": {
    "command": "要执行的命令"
  }
}
```

LLM 看到这个描述后，会决定"我需要用 bash 工具来执行 `ls` 命令"。

> [!note] 源码位置
> `packages/core/tools/` — 工具注册表和执行 pipeline
>
> `packages/shell/` — bash 工具的具体实现

---

### 2.3 Agent Loop — 工作循环（思考-行动循环）

> [!tip] 类比：解决问题的迭代过程
> 想象你在修一辆自行车：
>
> 1. **观察**：车骑不动了
> 2. **思考**：可能是链条断了
> 3. **行动**：检查链条
> 4. **观察**：链条确实断了
> 5. **思考**：需要买新链条
> 6. **行动**：去商店买链条
> 7. **观察**：链条买到了
> 8. **行动**：装上链条
> 9. **观察**：车能骑了
> 10. **结束**

这就是 **ReAct 模式**（Reasoning + Acting）：

```
观察 → 思考 → 行动 → 观察 → 思考 → 行动 → ... → 完成
```

在 Harness 里，这个循环叫 **Agent Loop**：

```
┌─────────────────────────────────────────────┐
│  Agent Loop（ReAct 循环）                    │
│                                             │
│  ┌──────────┐                               │
│  │  接收消息  │ ← 用户输入 或 工具结果        │
│  └────┬─────┘                               │
│       ▼                                     │
│  ┌──────────┐                               │
│  │  组装上下文 │ ← 系统提示 + 历史 + 工具列表  │
│  └────┬─────┘                               │
│       ▼                                     │
│  ┌──────────┐                               │
│  │  调用 LLM  │ ← 发给大语言模型              │
│  └────┬─────┘                               │
│       ▼                                     │
│  ┌──────────┐                               │
│  │  LLM 回复  │                               │
│  └────┬─────┘                               │
│       ▼                                     │
│  ┌──────────────────────┐                   │
│  │ 回复是什么类型？       │                   │
│  │                      │                   │
│  │  直接回答 → 返回给用户  │                   │
│  │  工具调用 → 执行工具   │                   │
│  │                      │                   │
│  │  工具结果 → 回到"接收消息"│                   │
│  └──────────────────────┘                   │
└─────────────────────────────────────────────┘
```

> [!abstract] 技术定义
> Agent Loop 是一个循环：接收消息 → 组装上下文 → 调用 LLM → 解析回复 → 如果是工具调用则执行并把结果放回循环 → 重复直到 LLM 给出最终回答。
>
> 这就是 ReAct（Reasoning + Acting）模式的工程实现。

## 3. 一个完整的例子

> [!tip] 场景：让 Agent 帮你查看天气
> 你说："今天北京天气怎么样？"
>
> **第 1 轮循环**：
> 1. Agent 收到你的消息
> 2. 组装上下文：系统提示 + 你的消息 + 可用工具列表
> 3. 调用 LLM
> 4. LLM 回复："我需要使用天气工具查询北京天气"
> 5. Agent 执行天气工具，参数：城市=北京
> 6. 工具返回：晴天，25°C
> 7. 把结果放回循环
>
> **第 2 轮循环**：
> 1. Agent 收到工具结果
> 2. 组装上下文：系统提示 + 历史 + 工具结果
> 3. 调用 LLM
> 4. LLM 回复："今天北京天气晴朗，气温 25°C，适合外出"
> 5. 没有工具调用 → 结束循环
> 6. 把回复返回给你

---

## 4. 为什么需要这三样

| 只有 LLM | 只有 LLM + 工具 | LLM + 工具 + 循环（Agent） |
|---|---|---|
| 只能聊天 | 能做事，但只能做一步 | 能自主规划和执行多步任务 |
| "北京天气是晴天" | 调用天气工具 → 拿到结果 → 结束 | 调用天气 → 拿到结果 → 判断要不要查穿衣建议 → 再调用搜索 → 综合回答 |
| 无法处理复杂任务 | 无法迭代 | 可以自我纠错、分步完成 |

> [!warning] 关键区别
> 普通的 LLM 调用 = 一问一答
>
> Agent = LLM 自己决定**什么时候该问、什么时候该做、什么时候该停**

## 5. Harness 的特殊之处

DeepSeek Harness 在这个基础等式上加了几个关键特性：

```
Agent = LLM + Tools + Loop
                + Session Log（完整日志）
                + Plugin System（插件化）
                + Multi-Agent（多 Agent 协作）
                + Sandbox（安全沙箱）
```

| 特性 | 作用 | 为什么重要 |
|---|---|---|
| Session Log | 记录每一步的完整日志 | 可回放、可调试、可恢复 |
| Plugin System | 一切皆插件，可替换 | 模型、工具、循环本身都能换 |
| Multi-Agent | Agent 可以委派任务给其他 Agent | 复杂任务分解 |
| Sandbox | 隔离执行环境 | 防止 Agent 做危险操作 |

> [!note] 源码位置
> 这些特性分别对应：
> - `packages/core/session/` — Session Log
> - `packages/core/agent-loop/` — Agent Loop
> - `packages/subagent/` — Multi-Agent
> - `packages/sandbox/` — Sandbox

## 6. 与 Agent.md 知识库的对应

你在 [[Agent]] 笔记里学到的概念，在 Harness 里的对应关系：

| Agent.md 概念 | Harness 实现 |
|---|---|
| LLM（大脑）| `ctx.llm` — 可替换的模型适配器 |
| Agent Loop | `ReactLoopAgent` 类 — ReAct 的代码实现 |
| 工具调用 | `ctx.tools` — 工具注册表 + 执行 pipeline |
| 记忆 | `SessionEventMap` — append-only 事件日志 |
| 规划 | `packages/plan/` — Plan 模式 |
| 反思 | `agent/pre-step` 事件 + 错误重试 |
| 日志 | `SessionEvent` — 每个事件有编号和时间戳 |

---

## 小结

```
Agent = LLM（能说话的大脑）
      + Tools（能做事的手脚）
      + Loop（能迭代的工作流程）
```

DeepSeek Harness 把这个等式工程化了，加了日志、插件、多 Agent、沙箱等特性。
